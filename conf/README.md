# 开发环境配置模板

本目录包含待实现配置契约的开发模板和已安装工具的版本证据。`examples/`模板的`runtime_ready=false`：游戏配置加载器、节点程序和业务迁移尚未实现；`toolchain/`则记录实际工具安装、PB生成及专属开发数据库的检查结果，两者分别维护。

工程布局为server/client，共享协议在shared/proto。模板内公共输入路径相对项目根目录；正式配置加载器应显式解析工程根/配置根，避免随当前工作目录变化而加载错误版本。工具命令由根目录tools/dev统一选择版本。

优先级见 `docs/架构适配与规则优先级.md`：最终策划决定玩法/数值/当前范围；当前项目架构决定技术参考。所有数值、字段目标和状态由配置目录统一追踪，模板中的引用不代表现有程序已支持引用解析。

`config/catalog/fragments/architecture.json`中的`id`仅为表内目录序号；`arch_protocol_ranges`分配的是原架构明确的消息号区段，具体协议消息ID由协议生成链另行分配。目录序号不充当运行时角色、物品、消息或业务操作身份。

| 文件 | 用途 |
| --- | --- |
| `examples/cluster.template.json` | 所有节点共用的非秘密结构；引用配置发布、预算、凭据和Mongo副本集 |
| `examples/nodes.template.json` | account/gm/game/supervisor的CLI参数形状，地址/ID/路径均待填 |
| `examples/secrets.references.template.json` | 环境变量/文件注入引用名称；不保存任何秘密值 |

## 使用步骤（待实现后执行）

1. 先实现schema、必填校验、拒绝未知字段和模板占位检测；没有有效配置版本或缺证书/凭据时不开放监听和经济入口。
2. 从模板生成本机私有副本，替换`<...>`占位；私有副本、密钥和连接字符串放受控本机位置并排除版本管理。命令行只传路径或引用名。
3. 用独立开发Mongo副本集建立数据库和最小权限账号，执行经审阅的迁移；事务采用snapshot读与majority写。连接字符串只从引用加载，日志不打印。
4. 落实account受控新授权、game直接续租既有授权；origin→run→node由Mongo持久控制流程管理，不把JSON改成动态路由真相。
5. 所有game使用同一共享配置内容和哈希；节点身份/监听/公告地址从部署参数传入。内部监听与公网分开、内部mTLS；监听地址不能代替客户端公告地址。
6. 按阶段验收后发布新的完整不可变配置快照。示例预算只用于试验；缺少实体/队列等必填预算时，目标场景仍关闭。

## 数据边界

- 公共配置：只读玩法表、资源映射和客户端必要字段，由Excel/schema生成；服务端专用字段不下发。
- 启动配置：模块类型、Worker/guard算法、传输监听、地图结构等按兼容性要求启动或维护生效；不能普通热更。
- 持久控制：路由、租约、封禁、计划、维护及合服，由版本化事务处理。
- 秘密：Mongo URI、内部节点凭据、签票密钥、管理员凭据、TLS私钥只从环境/受控文件引用加载。
- 运行态：room位置、HP/MP、Buff/CD、怪物、掉落、AI和随机流仅内存；模板不配置世界快照恢复。

金额固定采用0.1元宝整数单位、金币整数；在线不扣托管时长；共享仓按account+origin独立50格；双市场10%共用稳定税余数。PK、红名、公会/攻城、面对面交易、玩家互寄邮件和人民币提现入口不出现在可启用配置内。
