3. **目标拓扑容量与长稳。** 先用规则 28 复跑规则 26 的 5000 角色个人图口径，比较调度、队列、收益和增长趋势。候选再按架构建议单 run 1000→2000→3000 活跃角色递进，组合个人挂机、离线托管、共享城镇、世界首领、三人副本、双市场、充值与仓储，带轮换、重连和故障切换。按实际公共场景人数和实体谱验证上限与限流，世界首领 16 席是规则 28 候选值。正式混载至少 48 小时，跨上海日切；周／月／赛季边界另做可重复演练。端到端永久操作初始目标 P99 小于 500 毫秒，分别记录入场成功率、非预期掉线、MongoDB 写确认超时、队列年龄、CPU、内存、GC 和房间回收。长稳记录需解释预热后的变化，确认无持续失控增长及无账本差异。 [容量预算与口径](../架构方案.md#191-首轮容量基线) · [旧同机压测](13格挂机图托管合并结算复测.md)
