# M1 三职业技能与宠物验收

本阶段覆盖[首发里程碑计划](首发里程碑计划.md)中的三职业技能、职业宠物与施法补给。普通掉落、装备谱、成长经济及正式配置发布继续按 M1 计划推进。

## 规则 29 开发候选

- 战士 6 项、法师 14 项、道士 13 项均进入同一技能目录。99 条升阶规则按技能和目标阶读取唯一玩法工作簿，已学技能仍保留原编号与阶位。
- 书店使用正常金币报价、购买回执与原书学习，升阶使用对应技能书和书页。NPC 购书保留绑定和来源，仍受书页拆解门禁约束。
- 杂货铺按用途单位出售护身符、灰色药粉和黄色药粉，开发单价分别为 5、8、8 金币，每组上限 200。独立槽一次装一种耗材。护符用于道士的符系技能，施毒按装备的粉色决定毒效。手动与自动均在权威事务里验证来源、数量和实例版本，重试按原回执返回。
- 施毒和灵魂火符可列入自动策略。普通自动按当前目标、冷却和可用耗材决策，角色保留挂机位置，已有同色毒生效时跳过同色施毒。困魔、隐身、群隐、诱惑、启示及召唤保留手动入口。
- 法师可诱惑允许捕获的普通怪物，当前开发地图开放稻草人。道士可召唤骷髅或神兽，同一角色最多有一只活宠。新召骷髅消耗一张护符，神兽五张，同模板召回仍消耗魔法。换宠在确认新生后归档旧宠。新规则冷入场默认从无临时宠物开始。

## 联机检查

使用独立 MongoDB 8.0.34 副本集和真实 WebSocket，测试账号和数据在原试玩库之外。业务用例设定所需角色等级、金币和部分升阶书页，技能书、护符及两色毒粉通过真实 NPC 商店获得。

| 验收范围 | 已观察事实 |
| --- | --- |
| 战士 | 购买半月技能书、学习并升至 1 阶，实测手动和定点自动的攻击效果。 |
| 法师 | 火球术购书、学习并升至 1 阶，实测手动和定点自动。诱惑之光通过书店获取并升至 3 阶，实测收服稻草人。 |
| 道士 | 购买并学习施毒、火符、集体隐身，升至 1 阶后手动施放群隐，校验扣符和回执重放。实测火符、毒粉自动施放，另测错料、困魔和双粉色。心灵启示通过购书学习、升至 3 阶，在原怪物生命上生效。 |
| 道士召唤 | 正常购买两种召唤书并学习，神兽升至 1 阶。杂货铺购符后验证神兽新生扣五张、召回免符、健康重连保持生命身份、切回骷髅扣一张。 |

规则 29 夹具通过 162 项配置单测、584 项客户端应用及 UI 单测和 16 项场景单测。普通 Go 全包测试、`go vet` 和 Creator 严格 TypeScript 检查通过。

真实联机竞态回归分七组运行。首轮通过 38 个顶层用例，随后修复六个历史测试文件的规则夹具，将旧免费宠物明确限定在回归场景内。补跑其余 11 个用例后累计通过 49 个顶层用例。两轮生产源码与规则 29 夹具摘要相同，每批的独立 MongoDB 都已清理。

本机神兽序列加入后，Creator 3.8.8 重新构建了规则 29 Web Mobile 试玩包，用时 386.6 秒。保存场景布局与客户端脚本通过冻结核对。使用同一个 accountNode、两个 gameNode、各两个运行服，通过了实际 Chromium 触屏入场和区服路由检查。

测试入口见[三职业联机](../server/internal/integration/combat_m1_test.go)、[道士供给和施法](../server/internal/integration/taoist_mass_hiding_catalog_test.go)、[两种召唤的商店和重连](../server/internal/integration/summon_shinsu_catalog_test.go)。

世界首领重连先由新连接确认原个人图，再由服务端恢复同一首领席位。客户端进入世界首领时把个人图资源转交给返场缓存，重连确认个人图时继续保留原首领资源。重连等待按角色、连接代次与绑定隔离，在同一连接上跟随权威场景更新。原视图仍按场景生命周期释放，地图或规则不匹配时释放缓存。

最终双端浏览器验收通过。战士主动中断 WebSocket 后，以原角色、原场次和同一战斗实体重新确认首领席位。第二条连接的个人图基线确认用时 8 毫秒，原首领图基线确认用时 24 毫秒。这两个值从各自收到入场到发出匹配确认计算。该用例还通过了面板自动开闭、他职业活宠和尸体显示、地格占位与主动返回。

## 神兽外观和切换条件

按用户指定读取本机参考项目的 `79.Lib` 和 `80.Lib`。八方向出场、站立、行走、攻击、受击、死亡共 304 帧，按原动作表和脚点接入同一宠物渲染路径。真实 Creator 浏览器逐项验证了六种动作绑定原帧，并确认死亡进入地板层。技能学习、新生和护符扣除另有真实 MongoDB／WebSocket 用例。原图库和转换帧保留在本机试玩输入及部署包，代码版本库记录接入程序。导入与复核方法见[神兽外观资源接入](神兽外观资源接入.md)。
