# M4 成长商城隔离验收

隔离配置从功能页第三页打开成长商城。每个商品显示所用币种、单价、份数和当日额度。玩家先选数量，再核对总价和绑定结果，最后确认购买。商城沿用保存的详情页和原角色资产请求。 [策划 §4.12](../最终策划案.md#412-商业化与托管时间角色独立双卡) · [客户端操作](../client/assets/scripts/app/GameGrowthShop.ts)

## 商品与限购

| 商品 | 普通元宝每份 | 绑定元宝每份 | 隔离样本的角色日限量 |
| --- | ---: | ---: | ---: |
| 祝福油 | 100 | 200 | 3 瓶 |
| 技能书页 | 5 | 10 | 8 张 |
| 洗炼石 | 待核定 | 待核定 | 待核定 |

每份一件，四条价格来自唯一玩法工作簿 `game_shop_prices`。隔离装配取单笔最多 32 份，同一材料的两条报价共用角色日限量。服务器按确认的币种整笔扣除，余额不足时返回报价失败。书页从技能商店和书店 NPC 的旧报价并入商城，学习用技能书继续由原有渠道提供。洗炼石显示价格待定，拒绝报价。 [商品投影](../tools/resources/prepare_growth_shop.py) · [隔离限量](../tools/resources/testdata/growth-shop-isolated.json)

## 确认与重放

- 每个角色附着只保留最后一张报价，最长有效 30 秒，上海时间零点提前截止。首次提交复核场景、角色、规则、份数、钱包、当日限购与背包格数。角色文档只保存当前运营日的实际购买量。
- 绑定发货、钱包扣款、当日计数、操作回执和审计在同一事务内确认。掉线后用原操作编号和原报价查回成交，发货实例、币种与金额沿用原回执。背包不足时保留原余额与限购。

## 复验

在 Windows 项目根目录运行以下命令。联机脚本从锁定工作簿重建隔离商城并启动项目专属测试副本集。`body-training/result.json` 记录投影摘要、通过用例及副本集清退结果，位于脚本输出的 `.work/integration-batches/` 批次目录。

```powershell
.\tools\dev.ps1 python3 -B tools/server/run_integration_batches.py --group body-training --timeout 720
```

商城触屏用例通过 `creator_growth_shop` 构建标签启动，使用 `MINIMIR_GROWTH_SHOP_BROWSER_WEB_ROOT` 指向 Creator 实包，`MINIMIR_GROWTH_SHOP_BROWSER_MODE` 选择 `candidate` 或 `default`。候选同时将 `MINIMIR_GROWTH_SHOP_TEST_FIXTURE` 指向同一客户端公开配置所对应的隔离服务端夹具。原触屏报告和截图位于 `.work/growth-shop-browser-*/`。 [实包用例](../server/internal/integration/growth_shop_browser_test.go)
