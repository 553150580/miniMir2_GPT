# 共享城镇与任务图鉴

## 共享城镇

城镇在当前游戏进程内按运行服和地图编号划分。角色通过换图计划取得入口预留格，完成首基线确认后对同镇角色可见。地图、商店和安全区查询仍使用原有城镇配置。移动先申请目标格，成功后同步姓名、职业、位置和动作。离镇、断线和房间回收释放占位，健康重进会按保留位置重新申请。城镇人数预算由可走格数约束。 [共享场景](../server/internal/game/shared_town.go) · [联机用例](../server/internal/integration/shared_town_test.go)

## 任务与图鉴

点快捷栏「任务」打开保存的 Creator 面板。左侧选择主线、每日、成就、图鉴和活跃，右侧选择具体目标。图鉴按地图分组，复用已加载的怪物站立帧，首杀前显示剪影。面板显示服务端已确认的进度、绑定奖励和领取状态。主线按前置领取解锁。每日池有十项目标，每个角色每个上海运营日最多领取六项，活跃达到 100 可领取当日奖励。

击杀进度在原击杀来源提交时一并确认，在线和托管用同一条路径。回收、学会技能和等级目标读取已完成的服务端事件或角色数据。图鉴以怪物 ID 计数，归属地图用于展示分组。领取在原角色资产事务校验角色、运营日和目标进度，同一流水提交钱包、背包、状态和回执。重试沿用原操作编号。 [进度和领取](../server/internal/persistence/tasks_codex.go) · [客户端面板](../client/assets/scripts/app/GameTasksCodex.ts)

规则 27 开发配置从唯一玩法 Excel 导出三项主线、十项每日、一项成就、一项稻草人图鉴和一项活跃奖励。目标门槛和奖量为开发候选。图鉴永久战斗属性依赖统一养成预算。 [配置导出](../tools/resources/prepare_tasks_codex.py)

### 挑战任务来源

- 个人首领在首次写入成功终态时，同时记录原首领击杀、配置的通关目标和原死亡时刻。退出、超时及原终态重放不增加进度。旧活动预约仅在配置摘要、规则版本和模板生命与原数据一致时补认来源。 [个人首领事务](../server/internal/persistence/personal_boss.go)
- 讨伐链逐只记录四段阵容中真实发生的首次死亡。成功终态在同一事务校验原阵容和时刻，再给原队列中已扣次的真人计数。真人断线后仍按原参战资格处理。失败、退款和 AI 席位不增加角色进度。 [逐只核对](../server/internal/persistence/dungeon_tasks.go)
- 世界首领按原击杀贡献和原席位资格计数。是否抽中物品或进入奖励名次不影响已满足的参与资格。终态与独立世界计数同事务提交，计数按永久角色和入口保存，查询和领取时与其他来源合并。领取标记和绑定奖励写回原角色事务。 [世界计数](../server/internal/persistence/world_boss_task_progress.go) · [查询和领取](../server/internal/persistence/tasks_codex.go)

现有无筛选的野外击杀目标继续使用野外来源。新挑战目标可在唯一玩法表登记 `personal_boss_clear`、`dungeon_clear`、`world_boss_kill` 或 `challenge_monster_kill`。主线与成就在目标 JSON 内填写适用的模板、地图或怪物编号。每日表沿用目标事件列，筛选编号放在开放条件 JSON。图鉴继续按怪物编号累计，地图用于分组。客户端只在玩家查看时读取未预载的原版站立帧。 [事件装载校验](../server/internal/devconfig/tasks_codex_challenges.go) · [玩法表导出](../tools/resources/prepare_tasks_codex.py)

正式挑战任务目标、奖量及永久战斗属性预算仍待审定。规则 30 保持唯一 Excel 当前已登记的任务与图鉴内容。挑战目标、世界参与门槛和讨伐模板的新增用例使用独立验收配置。世界进度文档由 `world_boss_task_progress` 集合保存，备份、恢复与合服按永久角色和入口核验。 [角色世界进度键](../server/internal/persistence/world_boss_task_progress.go)

规则 30 的 M3 回归通过 78 项真实 MongoDB/WebSocket 用例。Creator 3.8.8 Web Mobile 的四服触屏验收还验证了普通任务领取，以及在原野外图查看林地守卫的 100×84 原版剪影。 [分批联机结果](../.work/integration-batches/92365de125db4160a8f88a91ba464a91/result.json) · [触屏结果](../.work/server-directory-browser-2547231913/server-directory-browser-report.json)

## 规则 27 的个人与世界 BOSS

个人 BOSS 的隔离配置通过正常协议提交预约。角色所有者确认场次编号、模板版本、战斗快照和当前执行权限后建立独享场景，客户端确认首基线后才开放移动和战斗。普通挂机世界保留并继续推进。首领实际死亡后由角色所有者提交终态和上海运营日成功次数，随后恢复原挂机场景。失败、超时和中断共用场次终态，重复请求返回原结果。开发用例使用隔离模板，正式资源、掉落、药水和材料消耗、自动挑战均待接入。 [个人 BOSS](../server/internal/game/personal_boss.go) · [场次事务](../server/internal/persistence/personal_boss.go) · [实战验收](../server/internal/integration/personal_boss_test.go)

当时世界 BOSS 验证了场次共享血量、命中去重、击杀及中断的互斥终态。后续规则 30 完成了同运行服的共享地图、永久终态和参与及排名奖励。 [世界首领永久结果](M3世界首领永久结果.md)

## 规则 27 历史验收

开发验证在隔离进程和数据库中运行。共享城镇用例覆盖不同账号入场、不同运行服隔离、待确认不可见、移动同步、占位竞争、断线释放和返回个人图。任务专项覆盖同一击杀重放、在线和托管计数、跨日领取、满背包事务回滚以及同账号双角色隔离。
