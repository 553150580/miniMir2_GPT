# 架构适配与规则优先级

日期：2026-10-26。状态：首循环部分实现并联调。已有真实Creator工程与Web Mobile构建、Go业务服务、Mongo+PB HTTP+WS链路及`-race`集成证据；完整架构、故障、容量、真机和全玩法验收尚未完成。

当前实现在显式development环境运行，正式`runtime_ready`和`production_ready`仍为false。浏览器登录和创建道士已通过，Array.from兼容修复已真实构建，入场握手修复后最终实测中，`development_loop_ready=false`。现状与证据见[正式开发推进记录](正式开发推进记录.md)；下列适配契约与完整发布阻断范围不因局部实现而自动解除。

## 1. 使用边界

本文件是两份原始文件的实施对照，不是新的策划案，不修改原始文件。`confirmed` 表示原文明确且当前采用的规则，不表示代码已实现；`candidate` 表示首轮实验参数；`unverified` 表示来源或行为仍需核验；`historical` 表示只保留解释背景。所有功能的实现与验收状态单独记录。

1. `最终策划案.md` V1.2 决定玩法、数值状态、权益、资产流转、当前范围及产品验收。依据：§0，L3–29；§5.11，L787–845。
2. 当前项目 `架构方案.md` 决定技术参考：单程序装配、模块、提交路径、协议骨架、租约、监管和压测方法。其内的产品规则须经过本表适配。依据：§1，L3–9；§18，L950–1005；§20，L1045起。
3. 上级目录工程、源码、数据和图片只提供可追溯参考；它们的旧托管、绑定、交易、PK等规则不覆盖当前策划。依据：最终策划§6，L934–940；§7，L957；附录C，L1384–1419。
4. 缺失或待核验字段不填造值。相关入口保持关闭，开发预览和模板均为 `runtime_ready=false`；只有实施、规则核验及发布校验全部通过才能另行发布。

状态解释：`adopt` 直接采用技术原则；`adapt` 按最终策划调整后采用；`defer` 当前范围不开放。适配后的最终规则仍以原策划对应条款为准。

用户在本次准备阶段明确服务端、客户端分目录：服务端工程根为`server/`，Creator工程根为`client/`，共享协议在`shared/proto/`。架构原文中的cmd/internal等目录相对server解释；原`api/proto`约定落实到共享目录，双端生成代码进入各自工程。配置、参考资料和开发工具继续位于项目公共目录，客户端样例素材位于`client/assets/imported/samples/`。

## 3. 开发时必须保留的约束

- 数据所有者、连接附着、room执行代次和角色永久归属分别建模；旧任务保留原授权，不升级epoch后重放。
- 普通挂机与特殊挑战共用战斗核心。挑战钱包/背包不是可写快照；其永久费用、奖励、次数和积分通过角色owner提交。
- 所有资产请求带稳定业务身份和请求指纹；未知提交保留预留并对账。查询暂时无记录不足以证明原尝试不会提交。
- 配置目录、协议、数据库索引及状态机的“已生成”不等于技能对拍、业务并发、发布或容量已通过。
- 示例监听、ID、路径只是待填模板；禁止把模板直接标记生产可用。
