# M2 支付订单与角色到账

现金商品来自玩法工作簿《双卡产品》。两类角色卡各有月、季、年三种期限，以人民币整数分保存报价。旧非绑定元宝月卡仍用自己的商品和扣款确认路径。规则 30 试玩默认没有现金商品和支付渠道装配。 [现金商品投影](../tools/resources/prepare_payment_cash_cards.py) · [策划 §4.3、§4.12](../最终策划案.md)

## 订单与对账

1. 账号授权和角色永久归属经数据库核对后，以账号及原请求生成稳定本地单号，保存原角色、永久入口、商品、金额、卡期或投放单位和配置版本。
2. 服务端接受渠道实际受理结果，绑定原商户和渠道单号。渠道通知只触发对已有原单的主动查单。
3. 核验服务查询配置中的商户，确认渠道付款状态、原订单、实付金额、币种、商品和原受益人。原渠道订单与实付交易号分别以渠道和原商户为作用域去重。查单超时保留原单；已付待到账订单出现有据的退款、关闭或错单时进入复核。
4. 当前持有原入口的运行服从已核验队列办理到账。角色修订、四钱包或卡期、订单履约指针、原操作和审计沿同一 MongoDB 事务提交。当前运行服、账号写围栏和原角色永久归属均在事务中校验。
5. 进程换代或原请求重试沿用同一订单与回执。已到账后再收到渠道状态变化，保留原回执并记录新对账观察，交由待确定的退款业务处理。

充值每一人民币分增加 10 个内部非绑定元宝单位。现金购卡只增加本角色的对应卡期。未到期续原期限，到期后从实际到账时重启连续期。卡期历史保留旧值，供托管扣时及战斗奖励按事件时刻核对。账号相同的其他角色仍保留各自权益。 [核验边界](../server/internal/payment/verifier.go) · [到账事务](../server/internal/persistence/payment_grant.go) · [原卡期历史](../server/internal/persistence/role_card_periods.go)

## 复验与发行条件

```powershell
.\tools\dev.ps1 python3 tools/server/run_integration_batches.py --group payments
```

这个批次从玩法工作簿生成隔离现金目录，便于在独立 MongoDB 副本集上用测试适配器复验错单、主动查单、并发重复到账和在线、离线角色投递。游戏服务器通过原 WebSocket 钱包和双卡状态向附着角色显示结果。 [联机用例](../server/internal/integration/payment_delivery_test.go)

正式上线仍需确认发行地区和渠道，接入获批商户及正式商品、充值档位、认证、HTTPS 通知、主动查单与退款，并核定已消费余额或有效权益的退款处置。支付发布门禁继续保留。 [发行核验记录](../最终策划案.md#6-平台与素材接入) · [正式发布门禁](../config/reports/正式发布门禁.json)
