# M1 成长、复活与原版外观

本次继续使用规则 30。成长联机采用默认玩法数据，从新建角色开始。1 至 3 级使用一只怪，随后通过正常设置切换到四只稻草人，使用初始武器和布衣。三角色各有 14 次实际怪物击杀结算，累计 210 经验，到达 7 级前均无死亡。各次经验读取真实击杀来源回执，装备磨损会独立推进来源流水。

| 角色 | 新角到 7 级 | 学习后实测 | 当时绑定金币 |
| --- | ---: | --- | ---: |
| 战士 | 2 分 54 秒 | 基本剑术学习及自动普攻 | 180 |
| 法师 | 3 分 06 秒 | 火球术手动与自动 | 90 |
| 道士 | 3 分 26 秒 | 在谷地南坡真实受伤后的手动与自动治愈 | 150 |

一级学习均被拒绝且保留原书，七级可消费原赠书并持久保存技能。三个角色在这一轮到七级时都未凑齐一阶材料。当前配方仍需额外两本同技能书和五张书页。以上只记录现行规则的新手到首技能路径；自然升阶供给及高等级成长节奏继续按 M1 验证。 [新手成长联机](../server/internal/integration/level_growth_m1_starter_test.go)

## 死亡与返回

- 普通图复活优先选择原配置出生格。活怪、活宠或其他共享占位挡住时，选距离最近的可走空格，同距离采用稳定行序。尸体仍可通行。原死亡编号、费用和生命代次处理沿用已验证路径。普通联机专项实测死亡后新票保持原死亡编号、正常复活和原操作重放。 [复活落点](../server/internal/game/revival_landing.go)
- 个人首领实际击败角色后，保存一份失败终态，原挂机身体、坐标和资产延续。原失败冷却仍可拒绝立即重试。世界首领战败返回原个人图，新票也不能重进仍开放的原场次，另一个在场角色继续行动。致死数值和窗口仅用于各自独立测试。 [两类首领战败联机](../server/internal/integration/challenge_player_death_test.go)

## 原版外观

| 对象 | 本机原件和映射 |
| --- | --- |
| 战士、法师、道士 | 原版 `Hum`、`Weapon`、`Hair` 基础分层动作。保留现有职业对应的基础造型。 |
| 银杏山谷、边界村、比奇城 | 21 位 NPC 按原外观号使用 `npc.wil` 和 `npc.WIX` 的 132 帧。 |
| 食人花、多钩猫、毒蜘蛛 | 本机原版 `10.Lib`、`6.Lib`、`12.Lib`。食人花原库无行走序列，移动时使用其原待机帧。 |
| 林地守卫、林地首领 | 试玩玩法名称保持，分别使用原图库中半兽勇士 `18.Lib` 和沃玛教主 `34.Lib` 的外观。 |
| 职业宠物 | 法师诱惑稻草人使用原 `Mon3`，道士骷髅使用原 `Mon4`，神兽使用原 `79.Lib` 和 `80.Lib`。 |

原图库只读。原版怪和首领生成 1,044 张非空原帧，带原索引、脚点、尺寸与来源摘要。三个原创原型怪及其生成器已移除。世界首领图集根据实际首领和场内可见职业、宠物重新制图，逐帧比对无损像素。 [怪物导入](../tools/resources/prepare_original_monster_assets.py) · [NPC 核对](城镇NPC原版外观接入.md)

同一套 Creator Web Mobile 包通过四服选角和五张地图的 10 次实际往返。三个城镇的 6、6、9 位 NPC 均绑定原版帧。两张野外实际显示食人花、多钩猫和毒蜘蛛，可把默认一只怪调到四只再恢复。该测试仅提高隔离角色的初始生命，保留原场景和怪物配置。

世界首领的两个无缓存浏览器分别用 1.80 秒和 1.63 秒从点击进场达到可操作。两端首次下载 9 页图集并绘制首领帧 `Hunt:34020`，战士端同时观察到道士的治愈术原帧。场次开闭、宠物和尸体、退场及原席重连通过。此次本机冷入场每端传输约 19 MB。

个人首领触屏实测绑定 `18.Lib` 的 `Hunt:18005`，主动退场后可查原战报。七组真实 MongoDB／WebSocket 竞态回归共 55 项通过。客户端应用与界面 594 项、场景 16 项和严格 TypeScript 检查均通过。各轮独立联机数据库已清理。

按安装位置将本机原图库一次性导入当前 Creator 工程，然后使用现有 `client-build`。PNG、图库和生成导入元数据保留在本机试玩范围内。

```powershell
.\tools\dev.ps1 python tools/resources/prepare_classic_actor_art.py '<原版 Monster Lib 文件夹>' '<原版 npc.wil 与 npc.WIX 的 Data 文件夹>'
.\tools\dev.ps1 task client-build
```

## 切图下载修复

跨版本停留的网页会继续使用旧 Creator 内存索引，原索引所指纹理包 `04b93fbfd.json` 在新版物理路径缺失。原试玩已补回原文件，校验 HTTP 404 变为 200 且响应 SHA-256 与旧包相同。五个目的地和对应返回共 10 次，使用无缓存隔离浏览器逐次完成首基线和场景确认。

新发布继续保留经旧构建索引认证且在新包缺失的历史导入和原生资源。新版玩法视图、图集索引和纹理变化时使用新物理 ID，旧 Cocos 索引继续请求自身匹配的字节。新页面从当前索引加载原版外观。 [旧资源保留工具](../tools/client/retain_preview_resources.py)
