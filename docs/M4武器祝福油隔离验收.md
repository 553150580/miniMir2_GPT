# M4 武器祝福油隔离验收

背包和穿戴槽可对同一件原武器报价。服务端按当前幸运向前一档，失败时保留 0 至 2 档、回到 3 或回到 6。两段分别累计实际消耗，第 100／3000 瓶仍按当档概率判定，下一瓶起每瓶提升一级。达到幸运 9 不再消耗。装备取得时的初始幸运保持原值，穿戴后按当前幸运刷新战斗属性。 [策划 §4.6](../最终策划案.md#46-幸运值最终规则) · [工作簿投影](../tools/resources/prepare_luck_oil.py)

报价显示原武器、投入的一瓶油来自哪个堆叠、成功率、失败回退、累计瓶数及结算后的归属。绑定授权在每次打开培养界面时关闭，按两次确认开启，打开后绑定堆优先，用完后可投非绑定堆。结算同一事务扣除一瓶、更新原武器版本和当前幸运、累计保底、必要时绑定并留下永久回执。失败回退也执行同样的绑定规则，重连重放返回原确认。穿戴武器发生磨损后，确认旧版本先保存磨损，再要求重报价。 [持久结算](../server/internal/persistence/weapon_oil_quote.go) · [触屏面板](../client/assets/scripts/app/GameWeaponOil.ts)

隔离规则使用候选祝福油物品定义和明确测试前态。默认规则 30 继续沿原目录。油的常规分解、战令及商城渠道尚未接通，武器的两段保底与翅膀养成分开推进。 [隔离物品输入](../tools/resources/testdata/luck-oil-isolated.json)

## 专项验收

```powershell
./tools/dev.ps1 python3 tools/server/run_integration_batches.py --group weapon-oil --timeout 360
```

真实 WebSocket 从背包武器第一瓶升到 +1 后穿戴，观察权威面板出现 2% 幸运。一次真实普攻磨损使旧穿戴报价失效，非绑油库存保持正确。对原 +4、累计 99 的武器用绑定油，隔离测试固定了隐藏抽样以复现第 100 瓶失败，收到回退到 +3 且绑定的永久回执。提交后关闭连接，新票重放当次请求只返原结果。第 101 瓶从 +3 到 +4，消耗非绑油时原武器仍保持绑定。另在独立持久层核对第 3001 瓶逐档达成 +9、界面和租约围栏及原回执审计。 [真实联机与持久回归](../.work/integration-batches/5ac43868d6e742f0ada7733041bce700/result.json)

Creator 3.8.8 手机视口实测从穿戴槽进入培养，第二次确认取消后保持关闭，再完成两次确认。实际消耗一瓶绑定油，木剑从 +3 升为 +4，权威幸运一击从 4.4% 更新至 6%。资产、原回执和审计相符。关闭再打开培养页，绑定开关重新关闭。 [触屏报告](../.work/m4-luck-oil-build/browser-oil-cc54ffbe7d324d0497a29eda80f49c11/result.json)

默认包通过背包与穿戴详情的入口关闭检查，也验证了四个区服的选服、入场和旧路由票拒绝。客户端严格类型检查和 724 项测试通过。 [默认触屏](../.work/m4-luck-oil-build/browser-default-144d0375e8b44b2e87fef120f8fb9083/result.json) · [四服入场](../.work/server-directory/1b09b43f144a4e4e99c17670ca268f8f/result.json)
