# M4 炼体伤害与吸收隔离验收

本阶段沿用生命、魔法炼体的报价、角色上限、绑定金币优先、提交回执和重连重放。伤害、伤害吸收加入同一份角色库存状态，旧档按零级读取新增系别。客户端在角色成长入口的详情列表切换四系，报价使用百分比，战斗属性页读取服务端最终生效的百分比。 [前置炼体验收](M4炼体隔离验收.md) · [策划 §4.5](../最终策划案.md#45-炼体p0-后段七系常驻成长)

## 来源与候选范围

| 内容 | 本阶段取值 |
| --- | --- |
| 伤害、吸收单次基础费用 | 3000、1500 金币，每 10 级上调一档倍率 |
| 原档位成功率 | 每档从 100% 开始，每升一级降 10 个百分点，失败扣费并保留等级 |
| 扩展伤害、扩展吸收 | 每组同类加算，各设 20% 候选上限 |
| 隔离伤害与吸收额度 | 各系每级增加 1%（100 个基点），各最多 12 级且受角色等级限制 |

唯一玩法工作簿提供费率、成功率和候选组上限。正式属性曲线仍待核定。隔离投影器在已校验的生命、魔法前置上追加两系，检查当前开放级数全部落在来源额度内。规则 30 默认包保持四系入口关闭。 [隔离投影器](../tools/resources/prepare_body_hits.py) · [核对样本](../tools/resources/testdata/body-hits-isolated.json) · [策划 §5.10](../最终策划案.md#510-小数值装备基础与全来源属性预算)

## 命中与结算

1. 先完成原物理或魔法命中流程，魔法盾、物防、魔防和饰物效果在原位置计算。零伤害继续按零处理。
2. 各系贡献先在扩展组相加并封顶，再用净伤害计算攻击方增伤。增量取整后，从增伤后的值计算目标方吸收并取整扣除。
3. 伤害进入正常扣血、飘字、盾削时和首领统计。普通场景读取已确认角色状态，挑战读取入场冻结属性。绿毒逐跳扣血与成功圣言术保留原固定效果，宠物按自身属性结算。

整型用商和余数计算百分比，避免大值先乘导致溢出。最终值在增伤和吸收完成后截在有符号 64 位范围。 [战斗预算](../server/internal/devconfig/expanded_hit.go) · [结算入口](../server/internal/game/expanded_hit.go)

## 实际验收

- 真实 MongoDB 和 WebSocket 经报价提交两个首级，重连取回原伤害回执。两笔累计扣 4500 金币，保留 2500 普通金币，MongoDB 只有两条炼体审计。
- 在个人首领的固定测试首击中，玩家输出由原净伤 139 变为 140，角色承伤由原净伤 120 变为 119。两次飘字与双方基线实际扣血一致，原生命、魔法上限和面板物攻数值保持原值。 [联机断言](../server/internal/integration/body_hits_test.go)
- Go 对拍覆盖组内合并、封顶、两次取整、极值、原魔法盾和防御、挑战冻结，以及绿毒、圣言和零伤害。
- Creator 3.8.8 的手机 Web 实包通过触屏选择四系、两次首级报价和确认、返回成长详情。战斗属性页显示「伤害加成 1%」与「伤害吸收 1%」，两笔回执和 MongoDB 原操作逐笔对应。 [触屏验收](../tools/client/verify_body_training_browser.cjs)
- 默认实包通过原成长详情和四服触屏入场。四个运行服分别落在两个 gameNode，每个 gameNode 承载两个运行服，原 Game 资源地址也通过兼容校验。
- 全量分批竞态回归通过 22 批共 128 个顶层用例。各批使用项目盘上的独立 MongoDB 副本集，验收后已清退。

完整导出校验仍受八项既有参考文件摘要差异影响。隔离投影的逐字节校验与联机测试有各自的记录。
