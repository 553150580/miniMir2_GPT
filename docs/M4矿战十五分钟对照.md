# M4 矿战十五分钟对照

在两层矿区和四种卡状态下配对角色。每对角色使用同一个绝对 15 分钟窗口、同等级战士、同一套木剑和布衣、同一四怪普通图，并通过正常协议学习技能、开卡和启用自动回收。首次附着前配平两端的金币本金与药量。同一配对使用本批独立 MongoDB 和真实账号、游戏 WebSocket。 [配对用例](../server/internal/integration/mining_horizon_test.go)

一组的本金恰好够买一把当前层工具，一层 50 金币、二层 80 金币。另一组按计划有效轮次和工具耐久准备整把工具的总价，一层 1,250 金币、二层 1,520 金币。每个矿工在窗内沿正常城镇路径向 NPC 实付购锄，矿区每 3 秒以 30% 的原概率判定一次。锄头耗尽再向同一 NPC 续买。资金不足时以正常报价确认拒绝，原角色返回林间战场，用窗口剩余时间打怪。工具采购、走城镇、排队、来回切图和停工均占同一 15 分钟。 [原矿区投影](../tools/resources/prepare_mining.py) · [策划挖矿参照](../最终策划案.md#512-金币长期产消参数与经济测算2026-10-20)

纯战斗角色在配对的同一窗口正常自动战斗。两端使用普通挂机采样的同一红药和免费复活规则。矿战只计实际进入钱包的矿物自动回收，黑铁及零价矿石记库存。对账核对实际购买前的钱包、锄头实例和耐久、每轮回收和击杀、红蓝药、普通装备磨损以及四钱包期末值。以原事件发生时间划窗，截止后的边界事件单列，仍参与四钱包复算。 [逐笔账本](../server/internal/integration/mining_horizon_ledger_test.go)

## 启动和复算

```powershell
.\tools\dev.ps1 python3 -B tools/server/sample_mining_horizon.py --seconds 900
.\tools\dev.ps1 python3 -B tools/server/sample_mining_horizon.py --replay .work/mining-horizon/<运行目录>
```

启动工具冻结本次使用的测试二进制和源码摘要。每种本金使用单独的 MongoDB，保留工作簿候选的摘要、每对角色的原账和清退结果。复算工具只读取这些原文件，重新核对四钱包、原墙钟、矿轮、实收矿和经验。 [复算工具](../tools/server/mining_horizon_report.py)

两种试用锄头的价格、耐久、等级及地图属于当前隔离候选。实验以实际购买的整把费用计现金流，期末剩余耐久单列。普通战斗的药耗和磨损保留物理数量，窗口钱包在补药和修理前截取。每组的城镇路线串行确认，排队时间计进原墙钟。正式工具生命周期、长期养成及真实市场供需另需运营窗实测。
