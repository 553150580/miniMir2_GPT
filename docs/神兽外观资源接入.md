# 神兽外观资源接入

规则 29 中神兽使用独立实体模板和外观键 `pet_shinsu`。开发包在该外观缺失时显示带有神兽名称和血条的几何占位，服务端仍按独立模板处理技能、训练和战斗。素材包包含八个朝向的站立、行走、攻击、受击、死亡和出场序列。

## 本机试玩使用参考原库

本次采用用户提供的本机参考工程中 `GoMir2_DS/.local/crystal-actors-src/Data/Monster` 的 `79.Lib` 和 `80.Lib`。`79.Lib` 提供出场、站立和行走，`80.Lib` 提供攻击、受击和死亡。工具按各自帧表与脚点导入六个动作，共 304 帧。当前试玩沿既有动作系统选取常态和战斗库。

将最新客户端复制到项目 `.work` 下的独立 Creator 工程，使用参考目录运行导入工具。目标路径指向该独立工程的 `assets/resources/development`。

```powershell
.\tools\dev.ps1 python tools/resources/prepare_shinsu_lib_preview.py <原库所在目录> --output <独立工程开发资源目录>
.\tools\dev.ps1 python tools/resources/prepare_shinsu_lib_preview.py <原库所在目录> --output <独立工程开发资源目录> --check
```

工具只读原库，源 SHA-256 记录在试玩资源清单。这个入口仅允许向 `.work` 写入实际帧、清单和 Creator 元数据，导入产物和 Web Mobile 整包均限本机试玩。参考资源的对外发行授权仍待核验。

Web Mobile 构建通过后，可以对隔离构建运行浏览器专项，检查六种动作是否绑定到对应 SpriteFrame。

```powershell
.\tools\dev.ps1 node tools/client/verify_shinsu_preview_browser.cjs <隔离构建报告>
```

## 接入有权发行的独立 PNG 帧

使用有权用于本项目的 PNG 序列。把清单和图片放在同一目录树，清单采用 UTF-8 JSON。

| 字段 | 内容 |
| --- | --- |
| `schema_version` | `1` |
| `provenance` | `kind` 为 `user_original` 或 `licensed`，`reference` 记录来源或授权依据 |
| `actions` | 包含 `idle`、`walk`、`attack`、`hurt`、`death` 和 `appear` |
| 单个动作 | `interval_ms` 为每帧时长，`directions` 含八组等长度的帧数组，从上开始顺时针 |
| 单帧 | `png` 为相对清单的路径，`sha256` 为原始 PNG 摘要，`offset_x` 和 `offset_y` 为相对于等距网格脚点的整数像素偏移 |

```powershell
.\tools\dev.ps1 python tools/resources/prepare_shinsu_assets.py <帧清单路径>
```

首次导入后，用 Creator 3.8.8 打开客户端工程，让资源数据库生成目录、JSON 和 PNG 的 `.meta` 文件，并确认 PNG 导入为 SpriteFrame。把导入后生成的 `.meta` 与其资源一同纳入版本库，再运行校验和 Web Mobile 开发构建。

```powershell
.\tools\dev.ps1 python tools/resources/prepare_shinsu_assets.py <帧清单路径> --check
```

使用 `--output .work/神兽资源验收` 可在独立目录检查 PNG 和清单。部署路径下的 `--check` 还会核对 Creator 的 SpriteFrame 和目录元数据。
