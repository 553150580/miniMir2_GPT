# 城镇健康往返与有界导航实施边界

用户已指定先接来源城镇与安全区，再启用角色绑定及瞬息移动。本阶段实现同一个角色owner的个人图与来源城镇开发往返；完整来源目录2、原始坐标、安全区几何和原生渲染沿上一阶段合同。城镇访问不是多人公共Line、完整NPC系统或野外PK，不从无怪推断所有伤害均受安全区免疫。

旅行分为目标资源准备、原owner收束事件、一次内存移交及新基线确认。客户端只请求已配置城镇或原个人现场，不上传任意地图坐标；准备不授权移交，旧连接、scene、life、过期或取消确认不得推动新世界。真正提交前收束已释放法术、攻击、击杀事实及永久操作；未知提交继续原job和原操作身份对账，不清预留，不借切图绕过。已经排队的旧经济命令仍沿原授权执行，新动作和经济请求在收束期拒绝。

健康切图不调用冷初始化或重新消费入场票据。旅行角色与现有单宠保留生命代次、HP、MP、动作时钟、攻击与法术冷却、状态、治疗余额、药效队列、使用水位及近战模式；死亡宠物不借换图复活。旧scene事件不重写为新scene，不补播旧命中。角色临时位置与所有上述战斗现场均不入库。

个人现场只保留一份有界内存：怪物及死亡事实、原返回点、地面目标、数量与自动状态、掉落及原截止。城镇期间不运行原个人AI，不补造攻击或收益；怪物复活和掉落寿命保持原服务端截止，返回后按当前时钟正常处理一次，不能重置计时刷怪或续掉落。城镇无怪，离线不扣战斗托管时长；角色既有状态及恢复沿真实时间规则推进。城镇宠物按合法地形跟随现存主人，不另造固定宠物出生点。

提交后资源或ACK失败保留已经移交的健康世界，不能默默回滚或满血重建。新连接仍经正常认证取票，按实际Entry地图重新挂载视图；来源首视口准备完成并核对binding、scene及baseline后才ACK。所有固定UI仍使用保存scene/prefab，旅行入口复用保存地图按钮和详情确认，不生成新固定布局。

城镇寻路采用增量有界搜索、静态连通分量与可复用工作区。静态图在准入前建立，每worker只持有显式数量工作区与有界排队槽，所有角色共用每tick总预算；路径构建与重新规划同样受预算限制。场景、生命或请求身份变化取消原任务；稳定不可达不在每tick重扫全图。个人17×17地图继续原有移动规则，静态禁止切角、动态占位仅阻目标格的语义保持。导航预算、内存大缓冲预留以及旅行等待仅维护唯一Excel中的开发profile，均属技术候选，不认证整体容量或墙钟时延上界。

初始随机新生池仍未认证，绑定初始化与安全区永久更新、21/TemporalFlux不在本阶段开放。安全区可观测几何和真正的永久绑定触发分别验收，不把客户端渲染、来源映射或配置生成称为完整业务通过。每阶段分别记录真实Mongo/WS、资源加载、ACK隔离、异常和实际触屏画面证据。

当前位置的安全区ID由服务端按来源顺序首匹配计算并随完整基线同步，0表示区外；客户端保持Long并验证同一基线各块一致。界面据此显示区内观察，不据此计算伤害或填写永久绑定。城镇导航的静态不可达或预算终止同步明确的失败终态，保留原目标身份、不伪报到达；旧失败不能清除新目标。

每个真实连接、会话及原scene保留有界的已接受旅行ID记录；取消或过期不遗忘它们，较晚的旧ID不能在另一个计划结束后重新创建。历史容量只维护唯一Excel，满时拒新计划而不淘汰旧记录。新场景在资源ACK前只推进原恢复与怪物/掉落截止，不启动新的移动、AI或攻击；收到匹配ACK后恢复原现场。该门禁不通过清空未知永久操作或重置战斗截止实现。
