# 角色绑定点数据基础实施边界

用户已明确选择“先建立角色绑定点，再按来源实现瞬息移动”，并于2026-10-28进一步指定“先接入来源城镇地图及安全区，再启用绑定与瞬移”。本阶段先实现永久数据与事务基础，当前运行配置仍为rule11、未包含绑定配置，21号技能保持关闭。来源服StartPoint均不在当前原图(128,128)起的17×17裁剪范围内；当前战斗图不新增绑定起点。

角色聚合新增可选`binding`，仅保存`map_id/x/y`。它是回到已绑定地点的紧凑业务事实，不是当前地图与临时坐标快照。普通移动、入场世界初始化、健康重连和故障重建不能从当前位置回写绑定；不保存HP/MP、路径、CD或场景代次。已存在的绑定不会因初始起点列表改变而被重设。读取原始BSON先检查三个完整整数字段，缺坐标、重复字段、浮点截断、越界及夹带临时状态均拒绝，不能解码成默认零坐标。

后续rule12及以后必须显式提供`binding.enabled/start_points`；关闭时起点数组为空，启用时必须有配置目录内的可走地格。地图、x与y必须明确，缺失/null不能补成0；显式(0,0)可以合法。当前目录只包含已配置个人地图，未知城镇ID直接拒绝；独立城镇及完整地图目录尚未接入。起点列表允许来源的重复项权重，不自作去重。

新角色在既有建角事务内同时保存绑定，原建角op重传返回原角色。旧角色缺字段时，只在合法game接管事务中补齐；它与票据消费、账号/run围栏、角色revision/CAS一起提交。重试事务外固定本次候选，已存在的业务绑定始终优先。不做启动时全表扫描回填，也不接入已有用户库或伪造历史绑定。

既有绑定的地图或地形无效时，入场事务整体回滚，绑定、票据、session与revision保持原态；不自动改为出生点。既有传输层在入场拒绝后立即关闭，队列内错误帧不保证送达。隔离测试分别核验正确错误帧或EOF，并核对节点仍健康及真实Mongo未接管/未消耗票据；这不表示错误帧交付问题已修复。

专项测试中的rule12及(0,0)/(2,2)仅是随机隔离数据库的输入，不是运行参数。唯一Excel、配置schema和生成器尚未加入启用数据；初始点审定后再逐项维护并导出。后续仍需绑定点只读客户端观察、安全区触发更新、地图目录与健康跨图移交，再实现200ms来源瞬移、占位落点及TemporalFlux。不得把本数据基础阶段称为完整绑定玩法或瞬移验收。

只读依据：Crystal PlayerObject.SetBind/SetBindSafeZone（1057–1068）、MagicTeleport（4633–4648），HumanObject转向/移动/传送后安全区绑定逻辑，SafeZoneInfo的Location/Size/StartPoint；MYF原始StartPoint.txt摘要`5da04adcfbc5e0024ddfb714ad2ddbd110e583f7cbbf7e20ee139c7d8d1a2050`。来源定位及数据事实不认证目标1.80或来源实服快照。
