# 审查修复与试玩音频验收

本记录保留当时的验收范围。当前试玩音频和导入方式见[原版音频接入](原版音频接入.md)。

2026-11-20，基线 `4fe40d5b`，开发预览规则 `rule23`。

## 本轮修复

- MongoDB 租约和仓储权限查询保留可重试错误。只有查无有效记录才判定失租或失去授权。
- 房间时钟丢弃早于计时水位的排队 tick。延迟命中造成的死亡以事件到期时间和原托管会话记账。
- 建角占用拒绝先持久化原操作终态，再以 `10006/4303` 返回。相同操作重查返回原结论，未确认的提交继续按原操作核对。
- 换地图附着时立即清空旧仓库和背包条目以及滚动位置。
- 配置导出拦截有效记录指向历史记录的悬空引用。启动探针退出超时仍走进程归属核验后的回收，首次启动和每次重启均对照本轮冻结的配置摘要与规则版本。

## 试玩音频

登录与选角沿用同一首原创循环音乐，进入游戏切换战斗音乐。按钮反馈、挥击、施法、命中和治疗各有独立音效。浏览器在首次触摸后开始播放，页面进入后台时暂停背景音乐，回来后继续。战斗音效跟随当前场景的权威事件。

音频资源在 `client/assets/resources/audio/`，可从项目根目录运行 `./tools/dev.ps1 python3 tools/resources/synthesize_client_audio.py` 重新生成。生成器只写本组 WAV，由 Creator 的 AudioClip 导入，保存场景与预制体布局保持原样。

## 验收结果

- 真实 MongoDB 和 WebSocket 全包 Go race 通过 1293 项，0 跳过。建角用例覆盖并发槽位竞争、占用拒绝持久化、释放名字后迟到原请求仍失败和新请求成功。
- 客户端 509 项、配置 148 项、恢复工具 4 项通过。客户端类型检查、Go vet 与配置及协议检查通过。
- 独立 Windows 启动及健康重连恢复探针通过。首次启动与故障重启共检查 21 个节点就绪响应。本轮隔离进程、临时配置和测试库均已回收。
- Creator 3.8.8 Web Mobile 实际构建退出 36，保存布局及构建期间主预览保持原字节。外层摘要窗口早于一次类型修正，原始报告保留该变化。修正发生在 Creator 进程启动前，另核对候选包内 source map 中 6 份改动脚本文本及 7 份 WAV 摘要与最终输入一致。
- 独立 Chromium 触屏通过 6 项。首触前静音，首触启动大厅音乐，登录和选角共享循环，入场切战斗音乐，返回选角恢复大厅音乐。正常装备木剑后，权威攻击和正伤害分别触发挥击和命中声道。7 份 WAV 均返回 HTTP 200，控制台 0 错误、0 警告。施法、治疗音效未进入本轮真实触屏用例，手机硬件听感仍待验。
- 本机 `18080` 已切换到验收后的网页包。首页与 7 份音频逐项通过 HTTP 核验，更新前后的静态服务实例和当时在线的游戏连接一致。正在运行的主游戏服务在下一次重启时加载服务端修复。
