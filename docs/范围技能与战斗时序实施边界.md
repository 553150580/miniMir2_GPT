## 3. 公式、范围与落点

共同公式位于`资料参考/crystal/Server/MirDatabase/MagicInfo.cs:180–221`：

```text
MPower = Bonus>0 ? Random.Next(Base, Base+Bonus) : Base
DefPower = PowerBonus>0 ? Random.Next(PowerBase, PowerBase+PowerBonus) : PowerBase
GetPower = RoundToEven((MPower / 4F) × (rank+1) + DefPower)
GetDamage(stat) = int((stat + GetPower) × (MultiplierBase + rank×MultiplierBonus))
GetDelay = DelayBase - rank×DelayReduction
```

随机上界不包含，Math.Round中点取偶，4F及倍率是C# float32计算。不能把最终GetPower的上下限当成等概率整数分布，也不能把本批小整数/倍率1可精确等价的实现扩大成任意C# float32全域复刻。大火球GetPower为`[12,13,14,16]`；雷电各阶最低`[11,13,15,17]`、最高`[16,22,29,36]`，其中rank1最高22.5取22；爆裂为`[10,12,14,16]`；群疗为`[6,9,12,14]`，其中6.5取6、11.5取12。

## 5. 动作、结算与报价的开发适配

源玩家`HumanObject.cs:1766–1768`攻击间隔为`max(550,1400-(AttackSpeedStat×60+min(370,Level×14)))`；普通攻击2974–2975分设AttackTime和550ms ActionTime，3201行延迟300ms伤害。普通怪物`MonsterObject.cs:2165–2171`动作300ms、攻击间隔用AttackSpeed、300ms后命中；移动2128–2131将ActionTime、MoveTime与AttackTime分别处理。数据字段和测试必须区分动作可用时刻、下次移动、普通攻击、共享法术和单技能CD。动画播放不能提前应用伤害，也不能因为异步报价暂停这些时钟。

本项目先校验状态/目标/距离/障碍/冷却/MP后再受理，拒绝不扣MP、不写CD、不发假受理；这是按最终策划施放管线的明确适配，不照搬Crystal部分时钟先写、目标后判的顺序。延迟事件使用场景、handle与生命代次隔离；单次群伤产生的多次击杀须逐杀留原事实、原配置/绑定/来源和稳定业务身份后串行owner结算，不能复用最后一个死怪或只结算一个目标。临时HP/MP、动作和位置不为本次修复新增数据库快照。

技能经济预览只申请一个有界PreviewInFlight槽并递增PreviewGeneration，不设置、清理或借用永久操作Pending；报价写入的是带TTL的临时确认材料，不扣资产。其I/O期间战斗、移动和既有恢复继续。回调必须匹配原room、完整Auth、原连接/Binding、场景和代次；健康断开与新连接绑定使旧预览失效，旧成功/错误终态不能给新连接发结果，也不能清后来代次的槽。并发永久变更可使预览revision过期，提交重查并明确拒绝；不通过暂停战斗维持报价有效。永久经济回执仍无TTL，旧TTL已删除历史不称可恢复。

客户端资源索引只作实现证据：`PlayerObject.cs:1690–1692,2858–2868`大火球Magic400起手、410方向飞行、570命中；`1708–1709,2956–2963`雷电Magic2 20起手、10命中；`1793–1795,2999–3002`爆裂Magic1650起手、1660地面；`1973–1975,3075–3078`群疗Magic1790起手、1800地面。精神力是被动。索引存在不等于1.80原WIL帧已导出/偏移正确/画面验收；保持原偏移与地图裁剪，不把高特效缩成命中范围。
