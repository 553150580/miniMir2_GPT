# 普通移动与动作时钟修复边界

本阶段修复普通移动的显示时长和攻击门禁，不开放抗拒火环、野蛮冲撞或瞬息移动。既有规则版本9、19项技能及唯一Excel数值保持；位移距离增长、绑定点、跨图与TemporalFlux仍须各自完成规则和实现验收。

## 显示步长与业务节奏

当前稻草人和变异骷髅的来源Walking均为6帧、每帧100毫秒。来源客户端按动画帧时钟播放，ObjectWalk通知不携带服务端MoveSpeed；服务端MoveSpeed决定何时允许下一次行走。此前把EntityState.move_interval_ms的1000/2000毫秒作为整步显示时长，导致六帧被拉慢。本次从已加载的形象Walking定义导出显示步长，不将当前两种形象的600毫秒推广成所有怪物的固定值。

普通相邻格仍沿已收到的权威路点插值，重复坐标不重启帧时钟，积压只在有界窗口内追赶，不向未知坐标外推。既有失焦恢复、跨格纠偏和死亡处理继续适用。这不表示推挤、冲撞或一格瞬移已有正确表现；它们需要显式权威位移身份及路径，不能借普通插值阈值实现。

## 动作、攻击与移动门禁

Crystal MonsterObject.Walk的普通行走会推进AttackTime至至少MoveTime；CanAttack检查ActionTime与AttackTime，不把MoveTime作为共享攻击守卫。此前本项目把NextMove直接加入攻击门禁，掩盖了普通walk推进攻击时钟的职责，并错误耦合了以后可能不同长的动作锁与移动节流。

本次普通怪物/宠物行走显式执行NextAttack=max(旧值,NextMove)，攻击入口只检查动作和攻击时钟。玩家普通行走既有ActionReadyAt=NextMove保持。原攻击、共享法术和单技能CD不得因解耦而缩短。当前Go调度沿用截止时间相等即可受理；来源怪物严格大于的区别保留为本作适配。

回归中的动作300毫秒/移动500毫秒只构造两个时钟分离的前态，并不表示已实现推挤，也不新增一份可维护的玩法参数。普通walk回归必须实际执行walk，不能仅伪造NextMove后推断来源行为。

## 地图与布局保持

本阶段核对当前17×17菱形场景：四件原尺寸小设施/装饰位于四周；中央无大型遮挡，旧大树及其旧碰撞已移除，4个运行阻挡与285个连通可走格保持。名字Label24、保存预制体缩放0.7和各自稳定头顶位置保持。10份已保存场景/预制体须在构建前后逐字节一致；窗口增加高度仍只增加战斗视口。

来源定位：只读Crystal Client/MirObjects/MonsterObject.cs:1263–1285、Client/MirObjects/Frames.cs:21–25的DefaultMonster.Walking、Client/MirScenes/GameScene.cs:2304–2313，以及Server/MirObjects/MonsterObject.cs:2095–2134和CanAttack/CanMove。精确相对路径、行段与文件摘要随阶段来源记录归档。以上仅证明当前提取子集，不认证完整目标1.80、真机流畅度或全部位移技能。
