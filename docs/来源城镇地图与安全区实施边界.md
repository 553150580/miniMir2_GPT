# 来源城镇地图与安全区实施边界

用户已指定先接入来源城镇地图及安全区，再启用角色绑定和瞬息移动。银杏、边界村和比奇均属MYF地图号0“比奇省”，原图尺寸700×700；安全区不是独立城镇边界。运行目录另分配地图2，保留完整原坐标；个人战斗地图1继续17×17，不把289格安全区窗口冒称完整城镇，也不把窗口宽高用于来源瞬移。

渲染与碰撞共同读取MYF服务端0.map独立副本，摘要`2780766485d1e047dc2e8f03578ee83c6a14fd91597fe4562329cb8f24e1d4ec`；图像只读现有客户端地图WIL/WIX及mmap小地图库。客户端旧0.map与服务端整图不同，即使银杏局部逐格相同也不合并来源身份。这是可追溯跨来源开发候选，不能认证来源实服画面或目标1.80。

来源城镇保持原生48×32矩形格及图像切片拼接，源y向下，原点(0,0)，不把建筑切片逐片投影为菱形或重缩原帧。该来源非战斗城镇的表现与个人战斗图64×32菱形、48像素土层分开；后者保持用户约定。来源地图不加个人图土层与四周装饰。本阶段城镇配置不刷怪，不据此断言源码安全区对所有野怪、宠物或持续伤害统一免疫；野外自由PK继续关闭。

数值只维护唯一Excel。地图定义引用完整来源原图及摘要，碰撞表保存源资源描述与明确的关闭门策略，生成器逐格提取位图；不把几十万格塞入Excel单元格，也不维护另一本可编辑碰撞JSON。原始静态碰撞位、门位、运行合并位分别保留。地图分块16格，客户端并发4、缓存49块仅是显式技术候选，仍须视口及资源归属测试，不作为容量承诺。

地图门在本阶段保持关闭，运行位图将门格计入阻挡；门组、偏移和原格数据保留，不虚构开门、室内场景或NPC交互。实际引用的火把动画按来源基础100ms、各格tick和加色表现处理；普通地图帧不套实体WIL偏移，源码特例火把单独使用偏移。高建筑的实际绘制包围盒参与空间索引，不能只按脚点所在块加载。

安全区按来源StartPoint.txt中地图0的记录顺序保留，包括重复行；几何采用明确登记的Crystal含边界Chebyshev方形候选，重叠取首个。初始新生池和重复行的原服用途尚未认证，不能把所有安全区或重复行直接解释为新生选择权重。城镇开发入口采用来源银杏传送落点(633,613)，不冒称新生点或安全区中心；银杏绑定候选中心仍为来源(650,631)、半径8。绑定与21入口在城镇及安全区完成相应业务验收前继续关闭。

地图目录、地形查询、资源生成与客户端纯模型分别记录验收，不替代真实场景加载和同owner健康往返。真正切图还须保留角色/现有宠物的HP、MP、CD、状态、药效与生命代次，隔离旧scene输入/ACK/回调，保留原个人怪物与掉落事实，防止切图刷新或重复收益；城镇不作为离线战斗托管扣时场景。未经这些检查不能写为完整切图、完整绑定或瞬移已完成。

来源定位：MYF MapInfo.txt第5行地图0身份；StartPoint.txt第6–8、13、17行安全区；纯玩法传送资料第39行银杏落点仅提取地图号与坐标，不执行来源指令、不移植费用或部署逻辑。Crystal Map.GetSafeZone、Functions.InRange、Player.SetBindSafeZone及Client.GameScene地图绘制分支提供各自候选语义，按来源契约分别保存摘要。
