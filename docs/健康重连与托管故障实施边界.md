# 健康重连与托管故障实施边界

本阶段承接启动、入场与恢复子矩阵，依据《最终策划案》§4.1、§4.8、§7.4，以及架构适配A09、A10、A11。只补独立实际进程验收，不增加产品入口或故障注入接口。玩法仍为rule23，唯一Excel、配置和保存界面保持。

## 隔离前态

使用本任务专属MongoDB副本集，在新随机测试库创建项目标记，并为本轮account/game/gm分配新回环端口。仅操作经过映像路径、PID、创建时钟和命令行核验的自有进程。执行前后核对原主预览状态及Mongo身份；清理先停进程，再检查库标记和临时配置摘要。

通过正常注册、建角创建新法师，仅在首次附着前将该角色等级由1设为7，逐字段确认其它资格保持。原赠书学习、免费领取6小时、受伤、移动、耗蓝和托管均走真实PB/HTTP/WS及原资产事务。等级前态不代表自然成长验收，不写入现有开发角色。

## 健康现场观察

关闭自动后等待真实怪物造成存活受伤，正常施放火球，使用预签票进行健康新连接。比较首基线的Life、位置、MP和施法序号；HP允许持续受击导致下降，但必须仍存活、低于满血且没有上升。新连接不重播原CastAccepted。

在原施法动作门禁结束后、原1800毫秒冷却结束前尝试重施，必须返回原综合冷却错误，并记录单调时钟采样；原截止后还须真实受理一次施法。当前火球的共享法术冷却和单技冷却同为1800毫秒，因此只认证综合门禁保留，不分别认证两类时钟。正常在线阶段累计托管审计扣时必须为0、余额必须为21600秒。

## 真实进程故障

第一轮从存活受伤、耗蓝且离开出生点的在线前态强杀自有game。确认进程已终止，等待可能已经发往Mongo的事务收敛，建立稳定已提交边界。随后等待旧run租约自然到期，不修改租约，也不抢跑接管。重启game必须更换所有者并增加run_epoch。

冷新票先观察ACK前完整首基线，必须使用初始HP/MP、出生位置及新施法序号；Python在ACK前对照永久数据，随后ACK、暂停自动，再检查原领取重查没有推进版本、经济游标或重复加时。自然租约等待长于火球冷却，本阶段不据此证明故障清除了仍有效的冷却。

第二轮真实开启自动并关闭所有WS，观察至少2秒已确认离线扣时，再强杀自有game。自稳定提交边界到自然租约到期、以及新进程未附着窗口，角色、操作回执和审计必须全部保持；冷入场只允许正常所有者、run_epoch、session_epoch和revision接管变化，其余永久字段和全部既有回执保持。

## 账本与证据

角色、operations和audit_outbox使用同一个Mongo快照事务读取。每项收益回执和审计按`settle:<role>:<source_seq>`配对，核对来源序号及完整typed结算内容。余额必须满足`21600 - hosting_seconds = 审计host_seconds之和`。战报按托管会话建立，不能只用当前战报代替累计扣时。

故障窗口每次保留采样时间与摘要，使用规范扩展JSON保持BSON整数和日期类型。报告只保存安全观察和摘要；账号密码、token、票据和原操作正文只在探针内存中。代码、协议、工具锁、依赖、两本Excel及保存scene/prefab执行前后冻结。失败attempt原样归档，不能用后续成功覆盖。

重现命令：

```powershell
./tools/dev.ps1 python3 tools/server/verify_runtime_recovery.py --check
./tools/dev.ps1 python3 tools/server/verify_runtime_recovery.py --run
```

本阶段不认证强杀瞬间提交未知、毫秒级计费精度、维护、单room panic、网络分区、失租暂停再恢复、完整故障矩阵、手机真机或容量。至少2秒扣时本身也不证明离线击杀收益；实际观察到的收益须另按回执记录。完整P0和正式发布门禁保留，结果见《健康重连与托管故障阶段验收.json》。
