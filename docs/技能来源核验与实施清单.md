## 火球与治愈的精确源码候选

以下是源码事实摘要，供实施时维护唯一Excel，不是第二份运行配置。`MagicInfo`未赋值字段使用C#默认值：DelayBase1800、DelayReduction0、MultiplierBase1、MultiplierBonus0，其他数值字段为0。

| 字段 | FireBall默认 | Healing默认 |
| --- | --- | --- |
| BaseCost / LevelCost | 3 / 2 | 3 / 2 |
| MPowerBase / MPowerBonus | 8 / 0 | 14 / 0 |
| PowerBase / PowerBonus | 2 / 0 | 0 / 0 |
| MultiplierBase / MultiplierBonus | 1 / 0 | 1 / 0 |
| DelayBase / DelayReduction | 1800 / 0 ms | 1800 / 0 ms |
| Range | 9逻辑格 | 9逻辑格 |
| 源Icon | 0 | 1 |
| 原生初始rank | 0 | 0 |

`MagicCost = BaseCost + LevelCost × native_rank`，源码还存在特定技能与属性的额外修正，不能向所有技能泛化。`GetPower = Math.Round((MPower / 4F) × (native_rank + 1) + DefPower)`；`GetDamage(stat) = int((stat + GetPower()) × multiplier)`。C#默认`Math.Round`采用中点取偶，不能直接替换为JavaScript `Math.round`或Go `math.Round`；中间浮点与最终截断也须保持测试可追溯。

火球先用角色MC上下限按`GetAttackPower`取值，再执行上述技能路径；治愈输入为角色SC取值的2倍，经过技能路径后再加施法者等级。无倍率/额外词条、原生rank0时，可用于单元测试的源码例子为：MC=1火球原始值5；SC=1、施法者7级的治愈额度13。这些只是给定输入的公式对照，不是所有角色的固定伤害或回血。

范围以`Functions.InRange`的`abs(dx)≤range && abs(dy)≤range`判断，即Chebyshev格距离，不能按屏幕像素或欧氏距离改写。火球`CanFly`每步朝目标移动一格并检查该格有效，不是Bresenham，也没有额外检查斜向两侧格，不能直接复用玩家“禁止切角”行走策略替代。治愈分支未调用CanFly，不应未经核验就统一加飞行遮挡。

火球命中排程为`500 + ChebyshevDistance × 50`ms；执行时仍需同图、有效Node、合法敌方，且目标离原目标格不超过2格，然后走MAC防御。`MapObject.GetArmour`的MAC分支还检查魔法抵抗，`MonsterObject.Attacked`有额外伤害、暴击等路径。抵抗权重默认10位于上级`Server/Settings.cs`第296行，第519行会被来源配置覆盖；该纯源码文件仅登记摘要与定位，不复制其完整运维域，也不读取源服配置实际值。只实现无抵抗/无额外词条子集时必须显式限定候选范围，不能称完整法术结算已还原。

源通用Magic先检查状态、已学、技能CD与MP，再扣MP；公共SpellTime固定1800ms，成功cast后更新该技能CastTime。来源范围检查存在对传入location和x/y非0的依赖，本项目应从权威目标位置校验实际射程，不能照抄坐标0旁路。源可先扣MP再发现技能目标不适用；若本项目选择拒绝无效目标不扣MP，应明确记录为开发校验顺序适配，遵循最终策划4.8先校验再确认施放的要求。

## 治疗队列必须与药品队列分开

HumanObject第4355–4363行先要求友方，默认无目标时回退自身；角色自己的宠物友方规则可定位至MonsterObject第2541–2544行。500ms后，CompleteMagic第6018–6026行再次检查友方、同图、有效Node及未满生命，再把额度加到`HealAmount`并以65535封顶。

人类目标的HumanObject.ProcessRegen第602–616行使用独立HealTime与HealDelay600ms，严格`now > HealTime`时，每跳恢复`min(remaining, 5 + floor(target_level/10) + floor(remaining/10))`。remaining随恢复递减，所以下一跳上限会变化，不能使用施法者等级或固定每跳额度。第641–645行满HP即清HealAmount，位于计时块外；第552行死者不执行恢复，死亡流程未清该队列，因此源码行为为死亡暂停、剩余保留。

怪物/宠物目标使用MonsterObject的另一恢复分支：第602行同样声明HealDelay600ms，第1430–1442行严格`now > HealTime`时仅恢复`min(remaining, 5)`，不含目标等级或剩余额度加成。第1416行死亡暂停，第1451行在计时块外满HP清队列。不能将人类治疗公式用于宝宝；MonsterObject第1420–1426行另有自然回血路径，本次治疗候选不因此自动启用自然回血。

源Healing延迟完成分支未显式检查目标Dead，可能向死者累计队列但不会令ProcessRegen复活；若本项目拒绝死亡治疗目标，必须记为开发合法目标收紧。满血治疗也可能先扣MP而命中时丢弃，不能把“满血不扣蓝”写成已存在的来源规则。施法者死亡、目标离图、延迟事件过期、健康重连与真实故障的处理需列独立用例，不借普通药阶段通过来替代。

默认生命/魔法同样可逐级按源码计算：战士HP为`int(14 + (level/4 + 4.5 + level/20) × level)`、MP为`int(11 + 3.5×level)`；法师HP为`int(14 + (level/15 + 1.8) × level)`、MP为`int(13 + (level/5 + 2) × 2.2 × level)`；道士HP为`int(14 + (level/6 + 2.5) × level)`、MP为`int(13 + (level/8) × 2.2 × level)`。这里除法与中间计算须按源码32位float语义，不能把所有除法提前整数化；最后才截断。不能据等级增长计算默认就擅自决定升级瞬间回血、切图回血或重连回血政策。

基本剑术只在已学后把原生rank×3加到准确；初学native_rank0时增量为0，不能因界面显示为技能1级就误加3。首批尚未开放升级时，rank1–3只用固定输入验证；当前0–3阶由owner材料升级取得，不能把固定输入测试当成玩家自然获取证据。被动收益须由ACAgility命中判定体现。源命中判定为随机整数`[0, targetAgility] > casterAccuracy`时未命中，防御再从AC范围取值。火球走MAC而非这条敏捷命中，不应为了共用函数把两种命中方式合并。

## 首批历史边界与当前后续条件

首批历史阶段交付“技能基础与首批三项开发候选”：显式技能/书身份映射、角色已学状态与owner幂等消费、职业MC/SC/MAC/准确敏捷基础、被动准确、火球敌方单体与治愈友方队列、技能CD/耗蓝、动作及效果事件、技能面板和必要操作入口。全部保持candidate，首批三项不冒充完整P0技能；当时首批以外只记录来源清单；当前已实现范围以上文21项为准，其余不自动开放。

首批资源核验开始时，开发manifest仅有站立、走、普攻、受击、死亡，尚未保存spell动作全集。该阶段随后补入真实施法资源，本阶段继续扩充原WIL刀光、方向与逐格效果；原要求仍保留：Crystal紧凑索引不能直接当原WIL帧号；火球起手、弹道、命中，治愈起手和目标效果须分别对原Magic包回读并核对。既有Magic格式样例与少量像素回读不能作为整套技能映射证据；新增提取与画面结果由本阶段后续资源和浏览器验收另记。固定技能面板、按钮和列表模板仍保存为Creator可编辑scene/prefab，代码只绑定与更新数据。

首批实证至少覆盖：7级附近的学习资格、错职业/无书/重复书、原实例与原op重放、被动准确前后命中分布、八方向和射程边界、斜角与飞行阻挡、施放中移动接管、MP不足和共享施法/技能CD、原目标移动两格与三格、死亡/离图/过期延迟、治疗动态分跳与满值清理、健康断线和真实故障、资源预载失败及保存布局不被生成器覆盖。成功记录应包含配置版本、固定随机输入、预期、事件与HP/MP实际变化、构建和浏览器证据；不只提交“生成成功”。
