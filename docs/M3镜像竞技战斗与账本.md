# M3 镜像竞技战斗与账本

镜像使用独立的菱形地图。攻守角色按同一套八方向移动、阻挡、命中、伤害、技能冷却和宠物战斗规则推进。角色和宠物保留原实体类型。战斗快照冻结有效装备折算、技能及等级、原参战宠物、可用药和施法耗材。临时损伤、药耗、耗材和战斗位置不写回角色资产。普通挂机房间照常运行。 [格战推进](../server/internal/game/mirror_combat_tick.go) · [原资产快照](../server/internal/game/mirror_combat_supply.go)

候选从同运行服、同永久入口的当季防守池中分发，排除同账号。客户端仅提交当天系统发出的候选编号。提交新版防守快照不更换已派出的旧版本。进攻角色确认首帧后才开始真实作战。健康新票接回原场实体、时限和序号。首帧超时和系统中断释放原预占，已裁决场次沿原回执结算。 [名单与原版本](../server/internal/persistence/mirror_arena_catalog.go) · [场次生命周期](../server/internal/game/mirror_arena_lifecycle.go)

工作簿确认每季 15 天、每日 5 次，胜利按连胜档计 5、6 或 8 分，失败计 1 分并清进攻连胜。防守结算只写战报。攻击和防守界面各读取最新 20 条，完整回执单独保留。隔离装配明确使用 3 名候选、1 分钟作战和有效存活生命比例的超时规则，同值由防守胜出。超时的双方生命分母在原场入场时固定。 [账本事务](../server/internal/persistence/mirror_arena_round.go) · [唯一工作簿投影](../config/README.md#镜像竞技隔离投影)

隔离 WebSocket 验收覆盖守方换槽、发布新版并下线后，旧版本仍实际释放火球。攻方在真实格战中掉线并用新票接回，普通挂机可与原场并行结算。另验证伪造候选被拒、认输计分、首帧超时退次和原结果重放。原结算已提交而旧连接未收到时，同角色新票可读回已确认终态。隔离测试使用明确的跨职业、等级差、宠物规则、赛季起点以及测试装备属性。 [真实联机用例](../server/internal/integration/mirror_arena_test.go) · [独立账本报告](../.work/m3-mirror-ledger/persist-268d298d33d24d46bfb00e2da690b38f/result.json)

界面在 Creator 保存了功能页入口、候选名单、攻守战报和独立观战视口。大厅可发布当前防守快照，查看已使用次数、连胜和积分。选定服务端发出的候选并确认后，客户端先准备原地表和双方职业资源，再请求预占。镜像地图挂载完成才发送首帧确认。战斗中可以回到普通地图继续挂机，或者确认认输，并在服务端确认后查看原结果。 [保存界面](../client/assets/scenes/Game.scene) · [大厅与观战操作](../client/assets/scripts/app/GameMirrorArena.ts)

镜像观战按独立场次核验角色、宠物、施法、攻击、命中、位移和有效火墙格。连接更换后仍以原挑战和战斗代次为准，只接收更晚帧。镜像画面、资源和镜头有独立生命周期，切换视口不会重建普通房间或改变其挂机设置。防守发布版本可在重新打开大厅时按当前赛季从原目录读回。 [会话身份](../client/assets/scripts/app/MirrorArenaSession.ts) · [独立表现](../client/assets/scripts/app/MirrorArenaPresentation.ts)

在启用镜像的 Creator 3.8.8 Web Mobile 独立实包中，两名角色通过触屏正常选服入场。法师发布防守后下线，战士选择原候选，确认独立 13×13 地图挂载后开战。观察到双方角色、守方火球和伤害飘字。战士用新票接回原场；普通挂机期间仍确认经验收益。认输只记一次挑战与 1 分，回原地图后攻守双方各能查看自己的战报。真实 WebSocket 与隔离 MongoDB 验收通过，副本集已清理。 [双端验收](../.work/mirror-browser/3c6155621af34698b558ee0efa86af3b/result.json)
