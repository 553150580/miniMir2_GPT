# 世界首领永久结果

每个运行服在创建首领和席位前，以原运营窗口、模板和执行代次预约场次。已裁决的击杀、超时或维护中断经同一个运行服租约写入 `world_boss_results`。记录包含配置版本、原开闭时刻、结算时刻、剩余生命、参战时间、有效贡献和原入场快照摘要。同一证据重试沿用原结果，冲突证据和失权旧进程的请求被拒绝。 [永久预约与结果](../server/internal/persistence/world_boss_result.go) · [场次队列](../server/internal/game/world_boss_ledger.go)

战斗结束后先显示「正在结算」。原结果确认后，玩家收到该场的击杀或超时和有效伤害榜。下一场仍按上海时间开放，首领面板的结果页可查看上一场成绩。提前击杀和强制中断均关闭该原窗口的入场。 [协议](../shared/proto/world_boss.proto) · [首领面板](../client/assets/scripts/app/GameBoss.ts)

优雅停服保存已裁决结果，仍在进行的场次按实际现场中断。进程崩溃时，新的运行服租约只确认旧预约中断，原生命和贡献显示未知或无榜。已确认结果和原场排行仍可读取。主动离开世界场时先撤销共享席位和输入，等待原普通挂机房间的在途扣料完成后再更新附着代次，避免扣除护符却丢失原施法。 [退场和回执](../server/internal/game/world_boss.go) · [停服结算](../server/internal/game/shutdown.go)

参与资格阈值、奖励组、羽毛和勋章碎片产量、装备供给预算、超时补偿与排名奖仍待唯一工作簿确定。本阶段交付原始结算事实和可查询排行，正式发奖依赖后续资格及击杀时卡状态的验收。 [策划世界首领](../最终策划案.md#418-boss-与讨伐链副本)

## 联机实证

在真实独立 MongoDB 上，一服两名玩家各打出 3 点和 2 点有效伤害共同击杀。二服同窗口已有 3 点有效伤害，尚未产生永久结果。强制结束隔离游戏进程，等待数据库原租约自然到期后，继续用同账号节点和 MongoDB 启动新游戏进程。新进程确认一服原榜、二服原中断，两个旧场均拒重新入场。两服各自正常进入下一场且仍可查原成绩。数据库核对四条唯一场次结果，同场伤害没有进入普通挂机奖励。 [强杀换代回归](../.work/integration-batches/m3-world-boss-durable-edbbff6dfb0149ed9645a97623ca3878/result.json)

独立存储竞态用例确认运行服隔离、同场争用、重放、原期限、旧租约拒写和原个人首领围栏。共享场退场另有受控回执回归覆盖在途扣料、重复回执和健康掉线两种分片顺序。 [存储竞态](../server/internal/persistence/world_boss_result_test.go) · [退场竞态](../server/internal/game/world_boss_return_test.go)

三服优雅停服实测覆盖三种状态。一服已确认的 5 点击杀结果保留。二服实扣 3 点、剩 2 点生命，随中断如实保存。三服在写围栏内暂缓确认，场内已判死并显示「正在结算」，停服等原击杀入库后才结束。重启后三场各有一份原结果，旧场均拒重入。 [优雅停服报告](../.work/m3-world-boss-graceful/mongo-c249f5fecd5842bcaf8aa032bf203176/result.json)

同一 Creator 包用战士与道士触屏实测冷入场、跨职业施法、活宠与尸体、同席重连。原窗口超时后，战士保持面板打开，道士回到普通图打开面板，两端均显示下一场预告和同一份上场成绩。历史包含原截止时刻与道士第 1 名、901 点伤害。 [双端浏览器记录](../.work/world-boss-browser-132117471/world-boss-browser-report.json)
