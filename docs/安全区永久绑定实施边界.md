# 安全区永久绑定实施边界

本阶段按用户“先接入来源城镇地图及安全区，再启用绑定与瞬移”的路线，承接rule13已完成的城镇健康往返。rule14仅开发候选，实施和验收分别登记；瞬息移动21、初始随机新生池、公共城镇AOI、NPC、统一安全区伤害免疫及容量验收不在本阶段结论内。

## 来源与触发

唯一数值源仍为`outputs/development-prep-20261026/`两本Excel。城镇目录2完整保留MYF地图0及5条有序安全区；区间采用包含边界的Chebyshev方形，重复来源行保留，按顺序选首个匹配区。

Crystal `Server/MirObjects/PlayerObject.cs:1064`的`SetBindSafeZone`保存当前地图与该安全区的中心，不要求StartPoint标记，也不保存当前脚点。`HumanObject.cs:2480/2605`的成功Walk/Run、`PlayerObject.cs:4264–4284`的合法Turn、`HumanObject.cs:6985–7028`的成功Teleport及`:2649–2720`的Pushed正常postamble具有各自触发；Pushed地形失败的early return即使保留成功移动前缀，也会跳过来源绑定postamble。

本阶段实际接入**成功普通Walk**。当前无独立Run/Turn业务入口；Teleport及Pushed的绑定钩子尚未接入，不通过通用relocate推定为已支持。出生、入场、健康旅行、复活和每tick安全区观察均不构造绑定事实。进入城镇的来源落点(633,613)位于安全区外，不直接授予(650,631)绑定。下一合法Walk落入安全区时提交该区中心；区外行走保留既有永久绑定。

来源ShoulderDash的安全区限制独立处理，不将冲撞归为Walk，不由成功冲撞产生绑定。来源`HumanObject.cs:5002`禁止进入安全区，本阶段修正此前仅检查地形的遗漏，按来源实际检查位置与退出顺序验证；失败消耗和动作锁仍走已有来源语义。

## 独立门禁与永久事实

`binding.enabled`继续仅控制原随机初始化，保持false且`start_points=[]`；rule14增加必须显式提供的`binding.safe_zone_enabled`，独立打开正常到访写入。缺省、null及未知字段拒绝。旧rule12/13仍保持原两字段合同，不隐式打开新业务。新角色和旧角色无绑定时可正常入场；不补成个人17×17出生点。

角色`binding`对象仍严格且仅有`map_id/x/y`。增加紧凑永久`binding_source_seq`，引用既有永久operations中的`binding:<roleID>:<SourceSeq>`回执；不存HP/MP/CD、当前脚点、路径、世界快照或临时布尔安全状态。回执保存实际区ID、中心、原图SHA、有序安全区集合SHA、合法动作事件ID及提交时规则/配置摘要。安全区数值只读Excel导出；集合摘要由既有有序目录计算，不产生第二数值源。

合法Walk完成后冻结原owner授权、场景/生命、地图、脚点、首匹配安全区、事件ID、预期revision、SourceSeq和配置身份。单个不可变事实占用原有Pending，后续移动和新业务按现有门禁暂停；不设无界绑定队列。旧待提交经济/来源任务按原次序完成，不改其操作ID、指纹或参数。绑定使用独立类型事务，围栏、角色revision/CAS、SourceSeq推进、角色中心更新、永久回执及审计原子提交，EconomicSeq保持。

未知提交沿原任务、原ID、原SourceSeq对账；重复读取必须核对类型、角色、事件及指纹，不以“SourceSeq小于等于当前”直接冒称原事实已成功。已提交事实不因连接后来断开或位置改变而丢失，旧回调不能清除新Pending。普通业务的单写所有者、续租和3秒事务时限保持。

冷入场核验严格坐标及引用回执。无来源证明但合法的历史绑定保持原值，可信资格为false；有正引用却缺回执、回执损坏或来源/中心不匹配则拒绝，不覆盖原记录。已有可信同中心绑定的后续Walk无需反复写库；同中心但没有证明时必须完成正式提交。冷验核原图及安全区集合身份，不因无关全局配置更新废弃合法旧回执。回执对应区ID由已核证明恢复为内存展示信息，不从当前脚点或区中心重新选首匹配区。

## 观察和客户端

新增纯S2C `BindingState`，携带RoleKey、当前scene、角色revision、该绑定回执SourceSeq、可空中心、cause、原安全区ID及trusted。所有64位字段保持Long/BigInt。cause1用于静默入场/新scene快照，cause2仅用于已经提交的新取得事实；客户端不能上传任意绑定坐标，也不能把实时safe_zone_id当作提交成功。

提交后服务端先发送同一最新Role的完整Inventory，再发送BindingState。经济操作继续按Inventory.revision构造，BindingState不改EconomicSeq、command序号、原Pending参数或确认水位。绑定观察按当前连接、附着、角色、scene及独立绑定版本隔离；新scene快照不补播旧提交提示。

复用已保存角色面板和系统消息显示“尚未绑定”、历史待核坐标或已提交中心，不新增或重排固定布局。相同可信中心后续走动不刷提示，健康重入静默恢复。21仍关闭，可信绑定只为下一阶段提供必要前提，不表示瞬移业务已经验收。

## 验收边界

分别保留严格配置、BSON/回执校验、真实Mongo事务及未知/围栏、真实WS动作与冷入场、客户端生命周期与Long、Creator实际构建和普通触屏路径的证据。生成成功、静态对拍和单测不替代真实业务结论。固定10份scene/prefab及来源地图/美术字节保持，阶段通过后再记录具体数量、提交并核对远程。
