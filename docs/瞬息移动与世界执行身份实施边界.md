# 瞬息移动与世界执行身份实施边界

本阶段承接rule14来源城镇与可信安全区永久绑定，按用户“先接来源城镇地图及安全区，再启用绑定与瞬移”路线推进21。rule15参数由本任务按已复制Crystal/MYF选择为开发候选，不冒称用户逐项审定、目标1.80完整认证、自然成长或完整P0通过。唯一数值源仍为两本Excel，实施与验收另行记录。

## 来源和受理时序

本作技能21映射Crystal的Teleport，职业法师，学习19级、原生0–3阶；学习与书本升级按既定本作规则，不恢复来源随机练功。书13对应MYF原《瞬息移动》，候选书价2000。初始仍只赠原三职对应一本，不因新增21赠书或预置技能。

Crystal `Envir.cs:654–656`、`MagicInfo.cs:18,219–221`及`HumanObject.cs:3375–3451,3537–3540,6096–6107`给出MP10+阶×3、600ms动作、1800ms全局/技能间隔及200ms延迟候选。新受理仍拒绝死亡、动作锁、冷却、MP不足和无可信绑定。MP仅临时现场扣一次，不引入经济命令、金币收费或永久MP账本。已受理200ms动作到期才判断当前地图NoTeleport及目的点；失败不退款，不添加成功状态。

200ms是候选动作Due，不是墙钟硬实时上限。本作保留原单写owner的永久Pending/未知提交冻结：若先前tick的kill等永久事务尚未确定，已受理21也保留原Due、MP和事件身份，待原job终态后的可执行tick才处理；不重扣、不重抽、不绕过永久围栏。此调度差异明确属于本作架构适配，不冒称来源跨对象调度或200ms准点保证。

来源Player.Die及Process链不清已接受ActionList，CompleteMagic Teleport分支无统一Dead门禁；同一真实角色、同Life、未Despawn的已受理动作可以在HP0时执行，成功仍保持HP0并添加状态。复活换Life不能承接旧动作。健康断线按本作既有已释放事件规则续行，冷重建不恢复临时事件。

## 目的点与状态

`PlayerObject.cs:4633–4647`到期读取绑定地图、中心及当时技能阶；每轴半径为目标图对应尺寸整除(阶+1)，分别从[-半径,半径)独立取偏移，最多200次，首次合法即停。越界、阻挡及重复样本均计次，不预裁界内，不改成当前17×17图随机空格或安全区半径。本次选择与一次性传送意图冻结后不重抽。

`MapObject.Teleport:780–800`及`Map.cs:121–143,637–643,2475–2485`只按原图静态Walk判点，不因动态占格或闭门额外拒绝。锁定MYF0.map按52B头、x外/y内12B格读取，back/middle/front任一0x8000置位为静态阻挡；源静态位图由同一文件派生，不另维护数值。普通移动保留原闭门候选位图；该闭门候选byte6与Crystal门索引byte8不同，本阶段不据静态核对认证门业务。传送可落在普通移动当前不可走的关门格，不能用客户端寻路资格否定服务器落点。

地图NoTeleport在唯一Excel每map唯一全图map_policy行显式提供。个人图1与城镇2当前均选择false候选；MYF MapInfo0行5仅NOMANNOMON、未见禁传标记，只是跨引擎文本旁证，不代表两引擎标记完全等价。缺字段不推定false，安全区五条来源行和绑定ZoneSetHash不混入地图政策。

成功后才添加TemporalFlux候选：固定30000ms只维护game_buffs.duration_ms，逐阶百分比30只维护value_by_level。重施刷新时长并保留原值，死亡、安全区和健康切图不清除；角色/owner销毁才释放。当前本人有效状态的最大传送耗蓝百分比只作用后续传送类：先算基础MP，再整数增加floor(基础×百分比/100)，不对普通技能加价，不由客户端倒计时自行撤销权威状态。源通用ManaPenalty的其他系统尚未实现，不冒称全部耗蓝状态已还原。

## World与观察身份

每个永久owner最多保留个人和Town两个内存World，角色值与宠物指针始终唯一，Role/Auth/Pending/永久队列仍同一所有者。World执行身份与客户端attachment scene独立；目标引用匹配原World、handle和Life。旧图没有幽灵Player/Pet可受击或再次施法。

全owner合并到期事件的Due/Order，同批首中末21均在其序位边界提交移交，再以同一实际now继续后缀；不因队列已被摘到局部批而丢事件，不等待未来弹道排空拖迟200ms。角色定向动作按来源同图条件明确失效；地图拥有的地狱火保留原图传播和唯一来源信用，保留事件不等于保证伤害。局部批、两World队列共享原事件预算，不因多次瞬移取得额外容量。

无事件休眠World维持rule13返回首baseline原现场、ACK后按原截止一次推进；仍有已释放地图事件的旧World只推进必要状态/截止和原事件，不开新Auto/怪物AI，不扣Town离线托管。Kill事实及奖励回调捕获OriginWorld，永久Role更新共用owner队列，装饰Loot写回原World，不能落到当前Town。未知提交保留原任务、原ID与指纹；旧回调不能清新槽或新owner。

## 成功落区与永久绑定

成功Teleport落入安全区按来源后置重新绑定该区中心。rule15新增teleport来源标签，仅允许当前已选已学21、合法职业/阶、原可信绑定序号和同绑定地图；不把任意内部传送标签当新生资格。旧walk/rule14回执与原JSON摘要保持，cold校验允许已核旧walk及新teleport事实；不增加递归证明链或临时位置永久存档。

绑定候选冻结动作事件和落点，在有界owner事实顺序中与旧图kill排队；仅队首正式受理时分配SourceSeq/ExpectedRevision，此后未知重试不改。同一到期批内的kill不会提早flush来阻塞21，未来未到期弹道也不要求排空；先前tick已存在的永久Pending仍按上述原屏障冻结。已有可信同中心不重复写库，SourceSeq推进不改变EconomicSeq。

## 客户端和协议

新纯S2C 30014 TeleportResult明确RoleKey、原/新scene、cast、Life、实际地图/位置/运动水位及结果；全部64位保持Long/BigInt。跨图成功先结果，再带同一server_transition_id的真实EnterLine及baseline。仅匹配当前连接、会话、角色、原scene和Life的结果可与新入场配对；客户端不能上传目的地图/落点，不等预载后再授权传送。同Town同World不换scene，继续由30013权威位移驱动。

服务器先移交并保留HP/MP/CD、状态、药效及原个人现场，客户端随后准备实际首视口、ACK、SyncReady后才解除新输入门禁。失败不自行退款或改坐标；健康新票静默恢复，不重播旧传送。跨图一次入场表现须当前World资源/首视口Ready及对应ACK就绪后消费，旧加载或旧回调只释放自身。固定scene/prefab不改，复用现有施法、状态、文字徽章与来源传送帧。

同World传送保留活动地面目标，从实际新格有界重规划，不因传送清目标或刷新其累计预算。跨图原目标随原World保存，新World不承接原地图坐标。

21合法落在闭门格后，服务端仅对该实际原图静态可走起点授权首步离开；点地寻路按合法出口做连通预查，目标、后续格和斜角仍使用普通闭门阻挡。该例外不改全局门位图，不接客户端指定起点，也不重置累计规划预算。
