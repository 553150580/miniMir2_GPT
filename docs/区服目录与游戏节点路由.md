# 区服目录与游戏节点路由

客户端登录或注册后读取账号节点的区服目录，选定永久入口，再查询该账号在该入口的角色。建角、待确认建角与角色资产操作仍按账号和永久入口隔离。入场及断线重连都重新取票，连接本次票据给出的游戏地址。分区负责目录展示，地图区域仍由游戏地图目录管理。 [最终策划案](../最终策划案.md) · [架构适配表](架构适配与规则优先级.md)

## 目录、路由和节点身份

| 数据 | 当前用途 |
| --- | --- |
| `origin_routes` | 永久入口服编号、分区和排序、入口名称、目标运行服及路由版本 |
| `run_servers` | 运行服的部署节点、公告 WebSocket 地址、部署版本及开放状态 |
| `run_control` | 当前获准承载运行服的节点、进程实例、运行代次、部署版本和租期 |
| `node_leases` | 以稳定 `game_node_id` 作为游戏节点唯一键的租约 |

账号节点用 `origin_server_id → run_server_id → game_node_id` 解析入场地址。目录中每个入口的可用状态来自当前部署、有效节点租约及对应运行服租约。签票时重新读取这些数据，票据绑定账号授权、角色、永久入口、运行服、节点、进程实例、运行代次及两个路由版本。游戏节点在消费票据和推进角色会话的原事务中重新核对。旧路由的票据需要重新取得，成功提交的原内部尝试仍可核对回执。

每次游戏节点启动生成新的 `boot_id`，同一部署重启沿用原 `game_node_id`。账号节点按持久部署记录批准注册，在同一事务中申请节点及运行服的独占权并推进所有写入围栏。同一启动实例重试会取得仍有效的原授权。当前运行时按每游戏进程一个运行服装配，持久目录已经可以将多个永久入口指向同一运行服。

## 本机配置

启动配置接受规范字段 `game_node_id`，旧字段 `node_id` 仍可读取。现有单服试玩可由原配置初始化一个入口。独立多节点装配让各进程共用同一个账号地址和数据库，各游戏进程配置不同的 `game_node_id`、`run_id` 和本机游戏端口。用 `origin_routes` 与 `run_servers` 提供初始目录，字段示例见回归测试。服务启动时对缺失记录做初始化，现有入口映射、部署版本和运营显示内容由数据库保留。 [配置校验](../server/internal/devconfig/topology.go) · [测试装配示例](../server/internal/integration/server_directory_test.go)

账号客户端协议新增 `10011/10012` 查询目录。原角色目录继续按入口服查询，入场票据响应追加 `game_node_id`。本机 WebSocket 可直接公告回环地址，单节点代理可通过受控分配公告同源 `/game/ws`。客户端使用服务端签发的地址，并阻止 HTTPS 页面降级到明文 WebSocket。

## 复现验收

从项目根目录执行以下命令。脚本启动、核验并清理独立 MongoDB 副本集，Go 验收在该副本集上启动一个账号进程和两个游戏进程。用 `--web-root` 参数指定项目工作目录内的独立 Creator Web Mobile 构建，可以再跑真实触屏浏览器验收。

```powershell
.\tools\dev.ps1 python tools/server/verify_server_directory.py
```

验收包括分区展示和离线标记、同账号在两个入口分别建角、按下发地址完成入场和首场景确认、串服票据、重复节点、竞争同一运行服、过期路由票据以及重新取票。迁服发布、正式证书与多运行服共用单进程仍有独立的实施与验收范围。

## 本轮结果

在独立 MongoDB 8.0.34 副本集上，同一个账号进程管理东区 101 和西区 202。两个游戏进程分别拥有 `game-east / run 11` 和 `game-west / run 22`。西区节点启动前目录标为不可用，注册上线后可进入。同一账号通过两个入口各创建一个槽位 1 的角色，目录和短票均对应所选区服。分别连接票据地址并完成首场景确认。

跨节点使用票据、重复节点、节点重复申请空闲运行服及另一节点抢占未到期运行服均被拒绝。推进隔离库路由版本后，旧票被拒绝，新票可完成接管。原启动实例登记重试保留同一授权代次。

Creator 3.8.8 独立 Web Mobile 构建成功。同一 Chromium 触屏会话分别选服、建角并进入两个游戏节点，两个首次场景确认均通过，页面异常为 0。Go 真实 MongoDB 竞态验收与浏览器组合报告位于 `.work/server-directory/d3840d3c85f94b6daef6fc01fb4e9b99/`，浏览器记录位于 `.work/server-directory-browser-1655149303/`，独立进程及副本集数据均已清理。
