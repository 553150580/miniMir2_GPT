# 区服目录与游戏节点路由

客户端登录或注册后读取账号节点的区服目录，选定永久入口，再查询该账号在该入口的角色。建角、待确认建角与角色资产操作仍按账号和永久入口隔离。入场及断线重连都重新取票，连接本次票据给出的游戏地址。分区负责目录展示，地图区域仍由游戏地图目录管理。 [最终策划案](../最终策划案.md) · [架构适配表](架构适配与规则优先级.md)

## 目录、路由和节点身份

| 数据 | 当前用途 |
| --- | --- |
| `origin_routes` | 永久入口服编号、分区和排序、入口名称、目标运行服及路由版本 |
| `run_servers` | 运行服的部署节点、公告 WebSocket 地址、部署版本及开放状态 |
| `run_control` | 当前获准承载运行服的节点、进程实例、运行代次、部署版本和租期 |
| `node_leases` | 以稳定 `game_node_id` 为唯一键，保存当前启动实例及获准承载的运行服与代次 |
| `game_boots` | 保存启动实例获准承载的完整运行服集合，为登记重试核对身份 |

账号节点用 `origin_server_id → run_server_id → game_node_id` 解析入场地址。目录中每个入口的可用状态来自当前部署、有效节点租约及对应运行服租约。签票时重新读取这些数据，票据绑定账号授权、角色、永久入口、运行服、节点、进程实例、运行代次及两个路由版本。游戏节点在消费票据和推进角色会话的原事务中重新核对。旧路由的票据需要重新取得，成功提交的原内部尝试仍可核对回执。

每次游戏节点启动生成新的 `boot_id`，同一部署重启沿用原 `game_node_id`。账号节点按持久部署记录批准注册，在同一事务中申请节点及整组运行服的独占权，并分别推进各服的运行代次和写入围栏。任一服被占用时整组登记回滚。原启动实例重试必须提交同一完整集合，取得仍有效的原授权。节点统一续租，受控停服时一并释放承载的运行服。

同一进程中的运行服复用 WebSocket 监听、房间分片、游戏调度和数据库执行器。引擎按短票的运行服、节点、进程实例及代次选择该服的持久化视图，绑定后房间继续沿用该视图。角色写入核对运行服与会话围栏，同一进程内两个运行服恰好具有相同代次时也能区分。目录允许多个永久入口指向同一运行服，角色与仓库仍按永久入口隔离。 [运行服上下文](../server/internal/game/run_scope.go) · [登记事务](../server/internal/persistence/game_registration.go)

## 本机配置

各游戏进程连接同一个账号地址和数据库，并分别配置唯一的 `game_node_id`、游戏监听端口和 `run_server_ids`。同一进程的运行服在 `run_servers` 中公告同一个 WebSocket 地址。现有单服配置可继续使用 `run_id` 和旧节点字段 `node_id`。服务启动时用 `origin_routes` 与 `run_servers` 初始化缺失记录，数据库保留现有入口映射、部署版本和运营显示内容。游戏节点的 `/healthz` 返回实际承载的 `run_server_ids`。 [配置校验](../server/internal/devconfig/topology.go) · [测试装配示例](../server/internal/integration/server_directory_test.go)

账号客户端协议新增 `10011/10012` 查询目录。原角色目录继续按入口服查询，入场票据响应追加 `game_node_id`。本机 WebSocket 可直接公告回环地址，单节点代理可通过受控分配公告同源 `/game/ws`。客户端使用服务端签发的地址，并阻止 HTTPS 页面降级到明文 WebSocket。

## 合服前市场清退

本机 gmNode 的 `/api/maintenance/market-merge/` 接受管理请求。使用 GM 原监听地址与节点凭据。源服和目标服在原账号目录中同时进入维护，并拒绝新票和未消费旧票。关门事务推进两服全部账号组的写围栏，和新签票、入场、市场命令及后台撮合确定提交顺序。已确认的市场操作仍可按原操作编号核对。 [GM 接口](../server/internal/transport/gm_market_merge.go) · [路由围栏](../server/internal/persistence/market_merge_plan_authority.go)

| 方法和路径末段 | 请求 | 结果 |
| --- | --- | --- |
| `POST prepare` | `plan_id`、`source_run_id`、`target_run_id` | 保存两服的部署和全部入口的版本，得到初始版本 |
| `POST freeze` | `plan_id`、`expected_version` | 原子关门。完成后对两个原运行服做正常停服和租约释放。当前按游戏进程停机，同进程承载的其他运行服也会断开 |
| `POST step` | `plan_id`、`expected_version`、`request_id` | 确认两服已无有效所有者，一次清退最多一笔。回执返回新版本，`done` 表示本步已看到两服排空 |
| `POST seal` | `plan_id`、`expected_version` | 复核租约、路由和托管余额，保存封账证明 |
| `GET status` | 查询参数 `plan_id` | 查看当前阶段、版本和累计清退笔数 |
| `GET route-release-proof` | 查询参数 `plan_id`、`expected_version` | 重新核对当前封账版本及市场条件 |
| `POST restore` | `plan_id`、`expected_version` | 从封账恢复两服的原部署，原游戏节点重新登记后开放入场，同时释放原计划门禁 |

计划和单步请求编号使用 32 位小写十六进制串。超时使用原计划、请求编号和版本核对。单步回执、市场返还待领奖、原托管终态和审计在同一事务提交。道具退回原件余量，竞购和金币委托退回各自冻结的原币种，已成交结果、税余数和原账本保留。恢复后待领奖仍归原角色，已退回的旧委托保持终态。 [清退账本](../server/internal/persistence/market_merge_assets.go) · [计划回执](../server/internal/persistence/market_merge_plan_steps.go)

封账证明覆盖双市场，实际合服仍需接通挑战和托管维护、掉落限额窗口汇总、赛季与活动处理、原子路由发布和目标节点恢复门禁。专项可通过 `./tools/dev.ps1 python tools/server/run_integration_batches.py --group market` 在独立副本集复验。 [双节点联机用例](../server/internal/integration/market_merge_gm_test.go) · [策划 §7](../最终策划案.md#7-技术方案)

新增签票围栏后，用规则 30 的隔离构建复测 5,000 个角色同时入场。16 路申请的首试全部成功，签票到首场景确认 P99 为 68.9 毫秒。随后在各自的 13×13 地图挂机 15 秒，在线最低 5,000，收益确认 P99 为 369.1 毫秒，MongoDB 事务提交 P99 为 13.1 毫秒，掉线和写确认超时均为 0。该轮使用独立压测进程的提高配额。 [压测运行记录](../.work/hosting-load/41a0b5fa9493497db86fb5132bb0e6ca/runner.json) · [压测指标](../.work/hosting-load/41a0b5fa9493497db86fb5132bb0e6ca/clients-prejoin.jsonl)

## 复现验收

从项目根目录执行以下命令。脚本启动、核验并清理独立 MongoDB 副本集。Go 验收在该副本集上启动一个账号进程和两个游戏进程，每个游戏进程承载两个运行服。用 `--web-root` 参数指定 `.work` 内的独立 Creator Web Mobile 构建可加入真实触屏浏览器验收。

```powershell
.\tools\dev.ps1 python tools/server/verify_server_directory.py
.\tools\dev.ps1 python tools/server/verify_server_directory.py --web-root .work/server-directory-client/creator/client-project/build/web-mobile
```

验收检查四个入口的分区、可用状态、建角、签票、入场和首场景确认，以及同一进程内的资产事务隔离、节点冲突和运行服争抢的整组回滚、旧路由票据的拒绝和停服释放。正式证书和运营迁服各有发布验收。

## 本轮结果

| 分区 | 游戏节点 | `run_server_ids` | 入口 → 运行服 |
| --- | --- | --- | --- |
| 东区 | `game-east` | `[11, 12]` | `101 → 11`、`102 → 12` |
| 西区 | `game-west` | `[21, 22]` | `201 → 21`、`202 → 22` |

在独立 MongoDB 8.0.34 副本集上，四个入口均完成真实短票入场和首场景确认。同一个账号在四个入口各创建一个槽位 1 的角色。运行服 12、22 的角色分别领取 21,600 秒托管时长，同节点另一运行服的角色余额保持原值。推进隔离库的路由版本后，旧路由票据被拒绝，重新取得的短票可入场。

重复节点、争抢同一运行服和跨节点使用票据均被拒绝。争抢运行服时整组登记回滚，原所有者继续有效。原启动实例重试维持两服原授权。停下西区后，21 和 22 一并离线，东区 11 和 12 继续在线。

使用同一份 Creator 3.8.8 独立构建完成三轮 Chromium 触屏复测。每轮逐服选服、建角并进入首场景，页面异常为 0，隔离副本集已清理。最后一轮组合验收记录位于 `.work/server-directory/a285bdf7094d4cababe21e7f97ebfe36/`，对应浏览器记录位于 `.work/server-directory-browser-2051450377/`。
