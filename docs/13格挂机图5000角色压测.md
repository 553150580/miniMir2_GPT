# 13×13 个人挂机图 5000 角色压测

2026-11-22 在 Windows 开发机测量，游戏代码基于 `a82e5bca`。使用规则 26 的林间战场，机器人通过真实 WebSocket 完成入场、首基线确认和自动战斗。每个合成账号对应一个角色。角色使用正式建角模板，预置为 45 级战士以持续承受 8 只原配置怪物的攻击。机器人不发送移动指令，每 16 帧场景快照核对角色位置。独立场景编号与游戏 worker 房间计数互证。

测试机为 i9-14900HX、32 逻辑处理器、约 64 GiB 内存。测试游戏服、压测客户端和独立 MongoDB 8.0.34 副本集分别使用独立进程。MongoDB 使用独立回环端口和数据目录，沿用 256 MiB WiredTiger 缓存及 128 MiB oplog。各进程共用这台机器和同一块物理盘。

## 接入与爬升

- 默认单进程接入 128 个 WebSocket，第 129 个返回 HTTP 503。默认房间配额为 8 个 worker，每个 256 间。压测专用构建把连接上限设为 5500、房间上限设为每个 worker 768 间。游戏服仍用 8 个工作协程消费容量为 256 的数据库任务队列，保留 3 秒应用事务截止和多数写确认。
- 边登录边挂机时，100／1000／2500 个角色分别持续战斗 20／30／40 秒，均零在场掉线。2500 个角色在 40 秒内收到 24,614 次击杀收益确认，数据库任务队列采样峰值为 86 项。
- 继续向 5000 个角色爬升时，共有 547 次新入场被游戏服以 `server busy` 关闭，226 个遇到失败的角色在重试后入场，86 个最终缺席。实际 4914 个角色保压 180 秒，全部有攻击和收益记录，共收到 127,719 次收益确认。期间在场掉线、MongoDB 写确认超时和应用事务最终失败均为 0。数据库任务队列峰值达到 256 项，入队遇满约 406 万次。该数字含同一任务重复尝试。

## 复测方法

在项目根目录通过锁定的工具链运行。第一条构建独立压测程序，运行器自动建立并清理专属 MongoDB。两种负载顺序需要分开跑，避免同时争抢 CPU 和磁盘。

```powershell
.\tools\dev.ps1 python tools/server/hosting_load/build.py
.\tools\dev.ps1 python tools/server/run_hosting_load.py --binary .work/hosting-load/hosting-load.exe --seed 5000 --hold 180s --profile both
.\tools\dev.ps1 python tools/server/run_hosting_load.py --binary .work/hosting-load/hosting-load.exe --seed 5000 --hold 180s --profile prejoin
```

每轮输出位于项目的 `.work/hosting-load/<运行编号>/`，其中有客户端事件、资源采样、MongoDB 与游戏节点日志。使用 `tools/server/summarize_hosting_load.py` 对指定运行目录生成汇总。
