# M4 分解祝福油隔离验收

普通装备的原掉落与装备培养共用同一种祝福油。手动分解有正耐久的幸运装备时，按原装备当前有效幸运除以 30 判定，每件至多一瓶。幸运 +3 的概率为 10%。本次确有油产出时继承被分解装备绑定，油瓶保留原装备实例号作为来源。 [策划 §4.2 与 §4.6](../最终策划案.md) · [工作簿投影](../tools/resources/prepare_recycle_oil.py)

手动分解已核实所有原件后，在同一事务移除装备、发放实际金币和油，并保存逐件判定、原产物回执和审计。满包时复用原件空出的格子，重连重试返回原操作结果。符合资格但未命中也有原回执。非绑定的装备分解油可按现行特权和资产规则存共享仓、上架和领回，原绑定油只能由当前角色持有。 [实际结算](../server/internal/persistence/equipment_recycle_oil.go) · [原背包面板](../client/assets/scripts/app/EquipmentRecycleOilModel.ts)

本轮用工作簿已确认的幸运概率配合原开发金币候选。可以识别的破损装备手动分解金币为 0，破损副产物和其他副产物的同次结算规则仍待明确。自动回收沿现行逻辑。默认规则 30 的原配置继续使用，分解出油入口和新的回执仅由隔离配置开放。

## 独立复验

```powershell
./tools/dev.ps1 python3 tools/server/run_integration_batches.py --group recycle-oil --timeout 360
```

真实 WebSocket 分别用有、无有效特权的角色击杀同一类普通怪，从原掉落回执确定入包的正耐久装备及绑定。单格满包手动分解后，油瓶补入同一格。提交后断线，新票回到原场并重放原回执，再用这瓶油将已穿木剑升到幸运 +1。只为稳定闭环，独立用例提高了掉落装备的初始幸运触发概率和分解出油概率。 [自然闭环](../.work/recycle-oil-natural-ws/5e21996aa833427ab90236254fcffe5b/result.json)

独立持久层复测采用工作簿原分母 30，核对满包中命中、未中及正耐久资格，零和历史负耐久都没有发金币或祝福油。非绑定原瓶经共享仓存取、市场托管、撤回和领回后保留原实例与来源。原绑定油的共享和市场申请被拒绝。 [真实持久回归](../.work/recycle-oil-persistence/8f9ea39714964cfaa1cf6a0294019521/result.json)

Creator 3.8.8 手机视口显示幸运 +3 原木剑的 10% 出油率及绑定，触屏取消确认后原装备仍在。用相同原分母实际分解两件有正耐久的 +9 木剑，一次未中、一次命中，实际拿到一瓶原绑定油。点开油详情可查原分解来源，原库库存、钱包、回执和审计均实测一致。 [触屏结果](../.work/m4-recycle-oil-build/browser-recycle-1680e39fc8594108ba763392cd44524c/result.json)

默认包的手机视口仍可打开原分解确认。取消后未产生经济请求，独立库的角色资产校验一致。同包验证四服选角、进场与旧路由票拒绝。客户端严格类型检查和 729 项测试通过。 [默认触屏](../.work/m4-recycle-oil-build/browser-default-76999198e7bc4cf29e3e1e382bbdb406/result.json) · [四服入场](../.work/server-directory/a172f3d9a17244a985aa23de7ef9438e/result.json)
