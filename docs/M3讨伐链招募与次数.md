# 三人讨伐链招募与次数

讨伐链招募按当前运行服隔离，支持 1–3 位真人。队长创建时选择模板、最低等级、可加入的职业和是否接受同职业队员，可在招募期间更新条件或踢人。接回使用同一角色的新票与确认基线，队长断线满 60 秒后原队解散。已满员和离线队长的房间不再出现在公开招募，成员仍能查原队。 [招募分片](../server/internal/game/dungeon_party.go) · [名单状态](../server/internal/game/dungeon_party_directory.go)

可选模板校验同一独立网格内的两段小怪、精英和最终首领。四个相邻战斗区须有可通行的边，每段使用互异的三个落点和已配置的挑战怪物。挑战怪不会沿用普通怪掉落、驯服和复活。两本工作簿的四档 30／40／50／60 级入口都缺模板引用，AI 能力档和费用也未审定。规则 30 的正式装配没有开放模板。 [装配校验](../server/internal/devconfig/dungeon.go) · [工作簿实读](../.work/m3-dungeon-rules/source-status.json)

MongoDB 入场事务逐一核验原队员、账号、角色修订、运行服以及场次执行代次。每天按上海运营日计 3 次，实际扣次时的有效托管卡加 1 次。一名队员不满足条件则全队回滚。同一原场次的重试沿用首次回执。普通失败和超时保留已扣次数，系统中断且原执行已隔离时仅按原入场日退还一次。新票须核对原场次和已保存的席位才能继续。 [入场事务](../server/internal/persistence/dungeon.go) · [终态与恢复](../server/internal/persistence/dungeon_lifecycle.go)

## 四段实战与回场

开战由原队长确认名单版本。整队扣次后，每位队员收到独立的场景和基线授权，先确认各自首帧，随后同场推进四个相邻小区。后一段在原怪物清空后开放，既有走格、斜角阻挡、攻击与法术按同场动作顺序执行。单疗能指向同队角色和宠物，群疗按实际覆盖格同步给原实体。原普通现场继续在角色所有分片内运行。 [开战协调](../server/internal/game/dungeon_start.go) · [共享地图与身体](../server/internal/game/dungeon_combat.go) · [输入和进度](../server/internal/game/dungeon_dispatch.go)

首次加载未完成时，系统按原日退款。全队加载后，掉线的身体继续自动战斗，新票重新确认基线后接回原血量、位置和阶段。通关、战败或系统中断经 MongoDB 确认后，各自回原地图。进程停服时收束场次，失权留下的活动场由新租约接管后在接收新连接前处理，已确认的终态保留。 [健康续接](../server/internal/game/dungeon_observation.go) · [回场确认](../server/internal/game/dungeon_finish.go) · [换代恢复](../server/internal/persistence/dungeon_recovery.go)

隔离实战使用测试模板和低血量怪物，三个职业共同清完四段，道士第二段断线后接回同一身体，三人返场各扣一次。另验证 5 秒原截止、未确认首帧的维护退款只发生一次，以及 8 秒副本到期时普通托管实际结清 7 秒。客户端组队界面、AI 补位、耗材技能原角色扣料、独立随机奖励、正式地图和怪物模板仍待完善。 [三人联机](../server/internal/integration/dungeon_battle_test.go) · [终态专项](../.work/m3-dungeon-durable/finish-230555661fec4aad82b40f07542ed809/result.json)

开战提交一度未知、原身份随后换代时，按同一入场请求核对退款。已确认退款的同队角色回填原持久状态，并继续原普通房间。最终服务端快照通过 76 项真实 MongoDB／WebSocket 分批竞态回归，测试副本集均已清理。 [最终联机矩阵](../.work/integration-batches/57e23f26ae6e4a5388ce2ddf6c806187/result.json)

Creator 3.8.8 Web Mobile 实构通过。在真实浏览器中，测试通过原队伍协议开战，再由游戏场景实际加载地图、确认基线、显示段号并回场。林地守卫仍用原始外观，世界图集未收录的帧先从旅行图集补齐，剩余帧才加载对应原件。该隔离场首次发来进场消息到客户端确认用时 916 毫秒，服务端就绪用时 922 毫秒。浏览器样本使用一个法师和隔离模板，三人同场另由真实 WebSocket 用例验证。 [浏览器实战](../.work/m3-dungeon-browser-qa/creator-run-1263296775/browser-result.json)

同包四服触屏回归中，个人首领面板的只读查询保持未完成，首次触摸离场仍发出一笔请求并返回原地图。离场后的中断战报继续通过其原入口读取。 [四服触屏](../.work/server-directory/b65aeeb020fd4d0b80ec208456a00241/result.json)
