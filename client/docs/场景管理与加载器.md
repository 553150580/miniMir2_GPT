# 场景管理与加载器

依据：用户2026-10-26客户端界面约定及补充“客户端要有场景管理加载器”，最终策划4.13、7.2和入场基线/ACK约束。本文约定基础模块边界和验收，实际Creator场景、预制体与构建仍在相应开发阶段提供。

## 模块边界

| 模块 | 职责 | 编辑器资产关系 |
| --- | --- | --- |
| SceneManager | 注册合法场景、协调切换、维护当前场景/切换状态、处理重复请求和失效回调 | 使用真实已保存的场景名称，不凭空创建场景 |
| SceneLoader | 异步预加载/加载、真实进度、错误反馈及任务生命周期 | 只加载已有资产，不生成固定节点或界面 |
| CreatorSceneBackend | 对接Creator 3.8.8的Director加载接口 | 注入真实director；不提供伪造的cc引擎声明 |
| 加载视图 | 显示当前阶段、ProgressBar、文字和重试反馈 | 保存为.scene/.prefab，代码只绑定引用和更新状态 |
| UIMgr | 管理普通弹窗及其返回次序 | 使用各面板已保存的prefab |
| PopupView | 管理详情/确认/帮助覆盖层，关闭后保留下层状态与滚动位置 | 独立覆盖层和半透明背景，无单独关闭按钮 |
| List / Tab / ViewStack | 可视条目复用、页签选择和内容页切换分别分责 | 条目模板保存为prefab；ScrollView/Mask使用内置组件 |

场景服务可为普通TypeScript对象。若后续需要持久节点，应在初始.scene中保存其根节点，再由代码注册已有节点；不得通过`new Node`补建固定UI层级。

## 加载和切换

场景名称先经过注册表检查。当前预加载和切换任务关联场景标识及本次请求身份；资产版本核验在后续资源清单接入时补齐。同一目标的重复切换复用正在处理的同一个Promise；不同目标在切换未完成时得到明确的忙状态，避免隐式连续跳转。

预加载进度来自Creator实际完成/总数回调。总数未确定时显示“准备中”，不除以0、不用定时器伪造100%；预加载完成与场景已激活是两个不同阶段。加载完成回调、切换状态及输入恢复只由当前有效任务提交一次。

取消只影响尚未进入引擎切换提交的逻辑任务。底层预加载未提供取消能力时，其回调可能继续到达，必须按任务身份忽略过期结果。已经调用引擎场景切换后，不宣称能够撤销引擎动作；待其明确完成/失败再处理下一次切换。

提交前加载失败应保留仍有效的旧场景状态，并允许显式重试。已经被引擎销毁的旧场景不能假装可回滚；提交后的异常要进入受控错误处理。加载视图、错误详情及重试交互使用已有编辑器资产和Button，不追加DOM或程序生成布局。

当前实现中，预加载失败、引擎返回false或明确的资源加载错误回调保留旧场景记录；调用`loadScene`在给出确定结果前同步抛错时，返回`LOAD_INTERRUPTED`并将`currentScene`设为null，表示真实场景状态未知，不能继续把旧场景当作有效。恢复流程须重新核对引擎状态或显式切换。

切换中通过状态通知输入协调层屏蔽重复点击；不添加电脑键盘监听。进入后台、失焦或尺寸变化只释放摇杆，不删除地面导航目标。场景加载器不持有或清理导航目标，当前场景的绘制和独立导航意图分别维护。

## 入场和资源归属

场景就绪事件交给入场流程。只有资源/场景就绪，且当前连接的scene_epoch、baseline_id和基线组装状态满足协议条件时，网络模块才发送EnterWorldAck。预加载结束不等于角色入场；失败、取消、旧连接回调不得发ACK，也不得申请重置服务端角色。

资源按场景/模块记录所有者。在新场景明确提交后，通过显式释放钩子释放离开模块自己拥有的资源；共享材质、图集、公共UI与新场景仍引用的资源不能随意释放。不能使用全局releaseAll清场。若缺少明确归属与释放适配，应保留引用并标明待接入，不伪称资源已释放。

关闭PopupView只弹出顶层详情/确认/帮助，不调用SceneManager重建底层界面、不销毁普通弹窗、不清除列表滚动位置。完整场景生命周期与局部弹窗返回是不同的操作。

## Creator接口核对

已对照本机Creator3.8.8实际源码：`cocos/game/director.ts`的`preloadScene`、`loadScene`签名，以及`cocos/asset/asset-manager/bundle.ts`中的场景加载接口。当前基础桥接以Director为边界；资源Bundle和引用计数在后续真实资产接入时明确归属后扩展。

结构化Director桥仅用于隔离引擎调用与测试。正式Bootstrap必须注入真实Creator director，注册实际可构建的.scene资源；模拟回调测试不能作为编辑器集成或真机验收结果。

## 当前脚本入口

三个实现文件位于`client/assets/scripts/core/scene/`：

- `CreatorSceneBackend.ts`接收真实director并转发引擎调用。
- `SceneLoader.ts`提供`preload()`任务、真实进度及`load()`启动结果；预加载任务的`cancel()`只取消后续逻辑。
- `SceneManager.ts`提供`registerScene()`、`switchTo()`、`subscribe()`、`cancelPreload()`和`dispose()`。加载开始后释放服务会等待真实结果，不宣称已撤销引擎切换。

固定加载页通过`subscribe()`接收阶段、当前/目标场景、真实进度和错误，再更新已绑定的Label、ProgressBar和Button。成功的`switchTo()`表示收到引擎启动回调，网络基线、入场确认及资源释放仍由相应流程接入。当前服务没有创建节点或自动释放缓存的代码。

项目根目录执行`make client-scene-test`，编译器使用Creator自带TypeScript 5.8.2，临时产物在`.work/scene-tests/`。2026-10-26实际严格编译通过，16项测试通过（13项顶层测试及3项错误模式子测试）。该目标也已纳入`make test`。

| SCENE02 | 同目标连点、不同目标抢切换 | 同目标复用，异目标忙拒绝，完成次序稳定 | 模拟Director测试通过，待真实场景验收 |
| SCENE03 | 注入资源失败、重试成功 | 提交前保留旧状态，忙标记释放，显式重试可成功 | 模拟Director测试通过，待真实场景验收 |
| SCENE04 | 预加载取消后旧回调迟到 | 旧回调不激活场景、不改新任务；入场ACK另验 | 回调隔离测试通过，网络集成待验收 |

SCENE02～SCENE05的自动化检查只验证服务层与模拟Director的异步行为。真实场景、内存/引用计数、手机输入、Web Mobile构建和网络入场另外验收，不因基础脚本测试通过就标为全部完成。
