# 战斗状态与三种护盾的来源契约

日期：2026-10-28。只读来源审计；不是运行数值源，未认证目标1.80。完整字段、行号与SHA见同目录source-contract.json；运行数值只维护唯一Excel。

本阶段三技能：MYF14幽灵盾/书28（源Price3500）、MYF15神圣战甲术/书29（4500）、MYF31魔法盾/书18（15000）。Price仅MYF字段候选，不能冒称本作正式商店报价。学习等级分别22/24/26、25/27/29、31/34/38；沿已有书本升级适配，不启用源随机练功。

幽灵盾与神圣战甲术：一次SC抽值×4+(rank+1)×50秒，MP2/4/6/8，中心半径3即7×7，距离延迟500+50×最大格距毫秒。仅每个受作用格要求源cell.Valid，中心阻挡不额外拦截，无视线检查。合法友方含本人/自己宝宝，原分支不排死亡但仍有Node的对象。增益是目标等级整除7再+4，只加MaxMAC或MaxAC；宝宝取模板Info.Level，不取主人等级或PetLevel。重施仅重设剩余时间，可缩短；不换原Stats，不重置LastTime/NextTime。

魔法盾：500ms后自用，MP35/40/45/50，持续秒为C#binary32后RoundToEven((MC抽值+15)/4F×(rank+1))，默认DefPower0。减伤20/30/40/50%在AC/MAC之前，以damage -= trunc(damage×percent/100)计算；正净伤再扣60毫秒/点剩余时间。已有盾时延迟回调直接返回，不刷新，源前置MP与动作/共享法术时钟已付。所有三技源动作600ms、共享法术1800ms，MagicInfo默认个人CD1800ms。

时钟关键：Buff.ExpireTime是剩余量。新建LastTime=actualNow、NextTime默认0。ProcessBuffs仅NextTime>now时跳过，相等会处理；扣now−LastTime，再置LastTime=now、NextTime=now+1000。扣后remaining==0即移除，只有正剩余且未标记才保留。受击或重施的AddBuff(existing)不重置这两个时钟；盾削负仍可保留减伤，直到下一次目标Buff处理移除。没有历史逐跳追赶。

源顺序不是全局唯一：Human先Buff(323)，再base动作(358/MapObject228–233)；Monster先base动作(1194)，再AI与Buff(1225/1227)；Map范围actions在Envir对象调度之后执行。ROOT已选实际处理时钟与约1000ms离散移除，不按原Due回造历史；统一房间phase顺序需标为确定性调度适配。

死亡：Player.Die635显式清魔法盾；另两种Properties=None，不随玩家死亡清掉，也不暂停扣时。宠物死亡不清Buff，尸体Node期间继续处理，Despawn后结束；不能据源玩家死亡杀宠顺带修改本作单宠候选。已有目标增益不能因施加者后续life变化全清；玩家保留状态跨复活须迁代，迟到施法仍受ActorRef隔离。

护符：GetAmulet只找已装备Type.Amulet、Shape0、Count>=1。ConsumeItem扣Count1，不扣CurrentDura。MYF187/188为Stdmode25、Shape5、DuraMax1000/3000，不能从中猜本作包单位或将durability当数量。ROOT明确采用独立slot100永久材料槽与owner原子扣除，是本作适配；包数量和价格已询问用户，未答不得激活猜值。

断线：源StopGame保留三种剩余Buff，重登重置LastTime，因此正式退出期间冻结；源还将其写在CharacterInfo.Buffs。本作按最终策划4.8健康托管继续推进，正常重连保留内存，不照搬源离线冻结或临时Buff持久化。未知提交期间的时钟策略须由主线另行登记，不从Crystal推断。

客户端已定位94个新增源表现帧，BuffIcon缺源不拿MagIcon同号替代；中文短名徽标由保存UI承载。资源转换、协议生成、真实状态/经济验收分别记录，不能用来源映射冒充已实现。

补充：源魔法盾500ms延迟回调没有Dead检查，玩家死亡不清ActionList；所以先施法再在500ms前死亡，源仍可能对尚有Node的死亡本人补新盾。本作game_buffs中31.allow_dead_targets=false明确拒绝此情形，属于已声明开发生命周期适配，不称源边界完全一致。
