# 共享协议实现状态

本目录是双端共用协议源。四份proto当前生成41个PB数据消息，消息清单包含35个消息号、24个错误码和3个后置保留消息，客户端有57个Long字段。当前已实现本地注册/登录、建角与目录、票据入场、基线ACK/SyncReady、网格输入、首循环资产结果、手动用药、首批技能owner学习与施法受理；完整职业技能/升级与两个市场协议继续按阶段补齐。

`EntityState.mp/mp_max`继续使用9/10字段号；`uint32 move_interval_ms=11`和`uint32 attack_sequence=12`是纯观察数据，支撑显示步进时长与攻击播放触发，不改变客户端输入权威。本阶段增加观察字段13 `cast_sequence`和14 `cast_skill_id`，独立施法身份用于动作播放。64位字段继续使用Long/BigInt。

药品阶段新增40009 `UseItemRequest`：字段1为原物品实例bytes，2为物品定义ID，3为uint64场景代次，4为`OperationContext`；复用40005 `OperationResult`确认永久消耗，不另建客户端回血权威。新增3101当前状态不能用药、3102使用间隔未到，仍为draft开发编号。客户端按库存顺序选原实例，服务端校验归属、数量、原场景、状态与共享节流；owner扣1提交后只向合法原场景加入分跳效果，同一操作或迟到回执不能重复消费、重复加药效或作用到另一个世界。

本阶段新增40010 `LearnSkillRequest`（原书实例、技能ID、OperationContext），复用40005永久操作回执；库存新增`LearnedSkill`列表，记录已学0级并以存在性区分未学。30003 `CastIntent`沿用并由技能ID表达首批技能意图；新增30006 `CastAccepted`携带场景代次、施法ID、起止格、方向、延迟和输入序号，仅描述已受理的临时施法，重连基线不重播旧特效。3201–3206分别表示未学、状态、冷却、资源、目标及输入过期，均为draft开发编号。移动与施法共用输入水位，服务端从权威目标位置判断射程、阻挡与命中。

当前实现与自动检查已通过：真实Mongo+WS全包`-race`为54条pass、0跳过且源码稳定，见[服务端报告](../../server/test-results/latest.json)。最终Creator3.8.8 Web Mobile实际构建144.12秒、退出36、源码稳定且7份布局不变，见`技能阶段验收.json`。浏览器首组关键路径已核对，首次状态变化观察仍保留追踪。药品、HUD和首循环保留各自历史验收；正式`runtime_ready`、`production_ready`和手机真机验收仍为false。

当前入场顺序为20002入场响应后先发送完整基线，此时连接Ready仍为false；客户端组装匹配基线后提交ACK，服务端仅在首次匹配ACK时激活并发送SyncReady，重复ACK忽略。首个基线不等待ACK，以免双方互等。客户端有界、乱序和过期基线组装已有测试覆盖。

消息号和错误码唯一源为 `protocol_manifest.json`。架构8.2明确的示例编号保留；新增编号仍标记`draft`，实现不等于正式发布。外层帧校验`binding_epoch`，世界消息另校验`scene_epoch`。当前本地开发传输为HTTP/PB与WS；架构目标中的HTTPS/TCP/WSS及正式证书配置继续按发布阶段验收。
